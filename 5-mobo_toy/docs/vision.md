## 1. 项目目标

构建一套**逐患者的非骨水泥股骨柄设计系统**。

输入:患者 CT
输出:该患者的**柄几何 + 锉刀几何 + 截骨导板/参数 + 目标对线 + 目标坐入深度 + 预测指标**

**产物是流程,不是零件。** 系统的价值在于对新患者可重复运行,而不在于找到某一根"最优柄"。

设计变量分三块,各管一件事:

| 变量 | 职责 |
|---|---|
| 柄 `S` | 刚度分布 → 应力遮挡 |
| 间隙场 `g(s,θ)` | 接触分布与预载 → 微动、界面应力 |
| 轨迹 `T` | 接触可行区 → 锚定类型 |

锉刀 `B = S ⊕ g` 与髓腔 `cavity = sweep(B, T)` 均为**导出量**,不是独立设计变量。

## 2. 当前阶段（2026-08 时的写法）

## 4. nTop 交互规范

### 4.1 唯一接口

```bash
ntopcl -j input.json -o output.json notebook.ntop
```

调试与排错时加 `-v2`,它输出逐块执行时序,可用于定位出错块与性能瓶颈。

### 4.2 契约文件

参数 schema **不在代码中手工维护**,由 notebook 导出:

```bash
ntopcl -t notebook.ntop      # 生成 input_template.json / output_template.json
```

两个模板文件提交进仓库。**所有编排代码只针对模板编写。** notebook 变更后由人工重新导出模板,再据此更新代码。

### 4.3 支持的输入类型

JSON 可传:`Boolean` `Integer` `Scalar` `Text` `File Path` `Vector` `Point` `Enum`。
标量与文本也可直接作为命令行参数传入。
文件导入/导出块请配合 `Text` 或 `File Path` 变量使用。

**标量必须带单位字段**(见第 7 节单位制)。

### 4.4 notebook 拆分

| 文件 | 频次 | 职责 |
|---|---|---|
| `instantiate.ntop` | 每患者 **1 次** | 骨 → 解剖标志 → 可行域边界 |
| `generate.ntop` | 每设计 1 次 | 参数 → 柄/锉刀/腔/网格 |

**禁止把两者合并成一张图**,否则骨处理会重复一千遍。

### 4.5 输出必须包含标量

`generate.ntop` 的输出**不能只有几何文件**,必须同时声明以下标量为 notebook 输出:

- 剩余皮质壁厚最小值
- 接触可行面积占比
- 柄的连通域数量
- 柄体积、腔体积、间隙体积
- 最小特征尺寸检查结果(布尔)

**约束判决在 nTop 内部完成。** 编排器只读 `output.json` 的数字即可判定拒绝,不解析几何、不传几何文件。

### 4.6 两遍分辨率

| 遍 | 分辨率 | 输出 | 用途 |
|---|---|---|---|
| 粗筛 | 粗 | 仅标量 | 约束拒绝 |
| 细建 | 细 | 几何 + 网格 | 仅对通过者 |

隐式/体素分辨率作为 notebook 输入变量暴露,由编排器控制。

### 4.7 GUI 调试开关

编排器中 `NTOP_EXE` 需可配置,允许在两者间切换:

```
nTopCL.exe   → 无界面批量运行
nTop.exe     → 带命令行输入打开 GUI(供人工排查)
```

切换后 GUI 会带着 JSON 指定的输入打开。**这是人工排查手段,Claude Code 只需保证开关可用。**

### 4.8 许可

nTop Automate 可能为独立许可条目,且可能需要 `-u <账号> -w <密码>` 或连接许可服务器。
编排器必须:
- 捕获登录失败并明确报错,不要静默重试
- 支持从环境变量读取凭据,**禁止硬编码或提交进仓库**

## 5. Abaqus 交互规范

### 5.1 主路径:`.inp` 文本模板

几何与网格来自 nTop,因此 `.inp` 是主路径。**优先用文本模板生成 `.inp`,而不是 Abaqus/CAE 的 Python 建模 API。** 后者只在需要复杂交互定义时才用。

```bash
abaqus job=<design_id> input=<design_id>.inp cpus=N interactive
```

### 5.2 双模型

每个设计生成两个 `.inp`,命名固定:

| 文件 | 界面 | 压配 | 分析步 |
|---|---|---|---|
| `<design_id>_bond.inp` | `*TIE`,`ADJUST=NO` | 无 | Step1 仅加载 |
| `<design_id>_fric.inp` | `*CONTACT PAIR` 摩擦 | **有** | Step1 仅压配 → Step2 保持 + 加载 |

**约束(不可违反):**
- `*TIE` 必须写 `ADJUST=NO`。默认 `YES` 会移动从面节点消除初始间隙,抹掉几何计算出的间隙信息
- 压配与外载**不得放在同一分析步**
- 从面取较软材料 → **骨为从面,柄为主面**
- 间隙区表面不加任何约束(既非 tie 也非接触对)

### 5.3 摩擦系数扫描

`μ` 作为模板变量,默认扫描 `0.3 / 0.5 / 0.8` 三档。

### 5.4 后处理

⚠️ **Abaqus 内置 Python 版本与 Abaqus 版本绑定,开工前必须确认。** 较早版本为 Python 2.7,较新版本为 Python 3.x。**不要假设,先跑 `abaqus python -c "import sys; print(sys.version)"`。**

**禁止在 Abaqus 内置 Python 环境里安装第三方包。**

后处理采用两段式:

```
abaqus python odb_export.py  →  导出 CSV(仅用标准库)
       ↓
现代 Python 环境读 CSV       →  分区映射、分位数统计、汇总
```

`abaqus/odb_export.py` 只负责把 `.odb` 里的场量导成扁平 CSV,不做任何分析。

### 5.5 许可

批量运行会长时间占用许可。编排器需支持:
- 并发上限可配置
- 许可获取失败时排队重试而非直接失败

## 7. 单位制(强制)

Abaqus 无内建单位系统,**全项目统一采用:**

| 量 | 单位 |
|---|---|
| 长度 | mm |
| 力 | N |
| 应力 / 模量 | MPa (= N/mm²) |
| 质量 | t (tonne) |
| 密度 | t/mm³ |
| 时间 | s |

骨密度量级参考:约 `1.8e-9` ~ `2.0e-9` t/mm³。

**nTopCL 的 JSON 标量必须显式带 `units` 字段,值为 `mm` 等,不得依赖默认。**

任何跨软件传递数值的地方,代码中必须有单位注释。

## 9. 运行记录规范

`results/runs.csv` **每个设计一行,无论成败**。必含字段:

```
design_id, 时间戳, provenance(sampled/fitted/manual),
<全部参数,展开为列>,
status, fail_stage,
t_min, 接触可行面积占比, 连通域数, 柄体积, 腔体积, 间隙体积,
```

## 10. 失败分级

| 级别 | 含义 | 在哪判定 |
|---|---|---|
| `L1` | 参数层拒绝 | nTop 粗筛,标量越界 |
| `L2` | 几何层拒绝 | nTop 粗筛,容纳/连通/最小特征 |
| `L3` | 网格失败 | 细建阶段 |
| `L4` | 求解不收敛 | Abaqus |
| `L5` | 后处理失败 | odb 导出或指标计算 |
| `OK` | 完成 | — |

**任何失败都必须写入 `runs.csv` 并保留 `runs/<design_id>/` 目录及日志。禁止静默跳过。**

（这套 L1–L5 分级现行流水线仍在用。）

## 12. 工作方式约定

**先跑 5 个,不要一上来写千例调度器。**

推进顺序:

```
1. 写只跑 5 个设计的最小编排器
2. 跑,把全部失败模式暴露出来
3. 逐一处理干净
4. 扩到 50 个探针,检查接受率(目标 ≥ 70%)
5. 通过后才放开到 1000
```

长任务采用**启动 + 轮询 + 汇总**模式,不阻塞等待单个作业。

排错时优先查 `runs/<design_id>/` 下的原始日志,其次用 `ntopcl -v2` 重跑该设计。
