# ADR-006 项目重组：不开新版，只重建控制层

**定于** 2026-11-04 用户"批准"，并改由提议会话执行（"你上下文的束缚较轻"）。

## 背景
按 NJU 生成式软件工程课的 10 组 agent 开发规范对照：FE 核心冻结得好，但入口分散（两份备忘 137 KB、两份计划 117 KB、没有 AGENTS.md）、批次代码 4385 行一个文件、没有 git 钩子和 CI、QA 长期 FAIL 无基线、判定靠口头、两个会话同改一个文件撞过车、Linux 上 204 个脚本只有 4 个在 git。

## 决定
- 不重写 FE 核心（8 个哈希文件、1292 行数据的作业号都依赖它）；只重建入口（AGENTS.md ≤ 600 字、STATE.md 脚本生成）、批次流程（提议 → 判据 → 批准 → 部署 → 喂料 → 导出 → judge → 记录）、门禁（PreToolUse、pre-commit、pre-push、deploy、QA 基线、数字复算）。
- 每批绑定交付物 D1–D8；细化候选每周 ≤ 20 槽时；重组总上限 4 天；研究日志原地冻结。
- 分工：实验会话只管 FE（改 v2/、tools/），重组会话只建 docs/ ops/ experiments/ conclusions/；git 写操作集中。

## 被否的方案
- 开新版重写：核心没有烂，作业号会全变。
- 全库覆盖率、bug 数据库逐类审查、调度看板、"喵"式指令、改写 git 历史：规模或场景不符，见提议第 6 节。
- 第 5 步（拆 stage_db、改名、归档 2D、第二根骨）：Gate 1 之后。

## 后果
- `code_hash` 的真身是 `docs/freeze/M1-3406-v1.json` + tar（5 个 CRLF、3 个 LF 的混合字节），不是 git 对象。
- 新批次改走 `experiments/`，`stage_db.py` 不再加批次。
