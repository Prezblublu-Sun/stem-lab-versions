# 提议：<批次号> <简名>

> 模板第二版（2026-11-11）。怎么填：
> 1. "必答项"每一栏都要答。答"不适用"可以，但要写一句原因。
> 2. 答案在看结果之前写定，和判据一起冻结。
> 3. 答案可以写"见某处"，但要指到具体的文件和节。
> 4. 必答项不设通用的阈值。做到多严由这份提议写，由用户批准。
> 5. 第二个模型审查时逐栏查：有没有答、答的和 `gates.py` 对不对得上。空着的栏算高严重度问题。
> 6. "固定门"不用填，由脚本查。

## 1 选点

有新设计的批次答 1.1。只有条件行的批次答 1.2。两种都有就都答。

### 1.1 新设计

| 项 | 值 |
|---|---|
| 策略名 | 一句话：怎么挑的 |
| 目标 | 优化什么量，朝哪个方向；有没有约束 |
| 用的数据 | db3406 版本；用了哪些行 |
| 用的模型 | 哪个代理；代码提交号；训练数据的版本；随机种子 |
| 候选从哪来 | 候选池的名字和大小 |
| 产出 | 行文件的路径；重跑能不能逐位相同 |

**P1 各种选法各多少行**

| 选法 | 行数 | 数据库里的选法类型 |
|---|---|---|
| 按分数挑 | | adaptive |
| 探索，按不确定度挑 | | adaptive |
| 随机抽 | | iid（行文件不许声明，要由代码里带种子的规则抽） |
| 单因素扫描 | | stratum |
| 合计 | 必须等于行文件的行数 | |

| 编号 | 问题 | 怎样算答了 | 答 |
|---|---|---|---|
| P2 | 随机抽的留多少？ | 写数。不留就写原因，并写明这批不能用来验证代理，结论只针对代理挑的点 | |
| P3 | 模型在候选所在的区域可信吗？ | 给证据：这一带的留出误差、覆盖率，或候选离训练行多远。没有证据就写"没有验证过" | |
| P4 | 候选不可行、或算了但失败，怎么处理？ | 两种都写。不可行的怎么筛；算了失败的喂不喂回模型。结局的类见 docs/runbook.md 第 11 节，读结局用 `ops/outcomes.py --json` | |

| P6 | 这条路线什么时候停？ | 写准则：预算用完、连续几轮没有改进、预期改进低于多少 | |
| P8 | 近邻间距和批内间距取多少，为什么？ | 写数和理由 | |

### 1.2 条件行

挑哪些已有的行去复核或换条件，也是选。

| 编号 | 问题 | 怎样算答了 | 答 |
|---|---|---|---|
| C1 | 按什么规则挑的？ | 写规则和脚本。规则要在看复核结果之前写定 | |
| C2 | 符合条件但没挑的有哪些？ | 列出来，写没挑的原因 | |
| C3 | 挑法会不会让结果偏？ | 比如挑余量最大的去复核，复算值多半会回落。写明读结果时怎么对待 | |

## 2 FE 必答项

| 编号 | 问题 | 怎样算答了 | 答 |
|---|---|---|---|
| F1 | 本批要分辨的差别有多大？同条件下的噪声有多大？ | 每个目标量写两个数和它们的比。比如"F：要分辨 3 mm，重划标准差 0.6 mm" | |
| F2 | 判据能不能不过？ | 写一种会让每条判据不过的真实情况，或给功效的估算。判据本来就几乎必过的，写明它拦的是什么、查不出什么 | |
| F3 | 有行失败时，每条判据怎么判？ | 逐条写：判不适用、判不过，还是照常判 | |
| F4 | 失败的行算不算结果？ | 按结局的类分别写。"没算出来"（网格失败、不收敛）：去掉记为不可判，或当成一类结果。"环境""出错""待查"不是设计的性质，不能当结果 | |
| F5 | 用哪些有效性量？超出多少，这一行就不能按数值用？ | 从数据库现有的列里选，写界限和超出后的用法。现有的列：`iface_force_err_load`、`iface_force_err_load2`、`open_frac_load`、`open_frac_load2`、`status_frac_stick`、`status_frac_slip`、`status_frac_open`、`F_n_nodes`。含义以 `schema.json` 为准。位姿和扭转的批次另写穿透和滑移 | |
| F6 | 本批有没有超出模型版本凭证的适用范围？ | 范围见 docs/model_scope_M1-3406-v1.md。没有超出：写"没有"。超出了才展开，每一项写一句"这一项没有做过收敛或对照，结论只作相对比较" | |
| F7 | 复核 | 三件事：本批里声称更好的行由谁复核，写"本批"或"哪一批"；复核几次、用哪档网格、什么算确认；没复核的行在结论里怎么用 | |
| F8 | 和哪些已有行比？ | 列出行或曲线 | |

## 3 固定门（不用填，由脚本查）

| 门 | 谁查 |
|---|---|
| 冻结完好 | `ops/check_freeze.py`，提交、推送、部署、喂料前 |
| 批次目录齐全；`approval.md` 里的哈希和 `gates.py` 对得上；行文件的哈希也在 `approval.md` 里 | 喂料门；判定时再比一次 |
| 管线文件已提交、已推，Linux 上的版本一致；行文件已部署 | 喂料门 |
| 完全相同的行不重算；参照行和基线行已算完；模板化可行；余量不低于下限 | 干跑 |
| 和基线行相比，物理只允许在声明的几项上不同 | 干跑。所以"为什么可比"不用在这里答 |
| 失败的行留在库里，带级别、阶段、原因、结局的类和名字 | 导出 |
| 判定时自动报：本批几行算完、几行失败、各是哪一类 | `ops/judge.py` |
