**依据**：《核心、插件和包》第五节（重建）和第十节第 4 步；[骨模型的写法](骨模型的写法.md)；《设定的声明和包的清单》第六节；
[改格式的分批](改格式的分批.md) 末尾（骨模型第 2 版并到这一步）；[拆内核](拆内核.md) 里留给这一步的几件。

## 现在是什么样

**骨模型（第 1 版）**：
- 恰好两个实体，名字写死是 `cortical`、`cancellous`；每个一种线弹性材料（`model`、`E_MPa`、`nu`）。
- 标志点必有五个，定义是一段话。
- 坐标系是四句话，只说骨源的坐标是怎么定的；实体不换系，没有“到解剖坐标系怎么转”的数。
- 没有覆盖范围（完整的股骨，还是近端一段），没有骨的种类。

**重建**（`plugins/recon/`）：
- 两种实验：`recon.draft` 从骨源出候选，`recon.finalize` 用上人工修改、过检查门、定稿。骨架、写骨模型、检查门是冻结的。
- CAD、CT 两条路都写在插件的自由代码里（`rebuild.py`、`ct.py`、`solids.py`、`landmarks.py`、`review.py`）。换一种重建的做法要改插件。
- 重建设定是一段没有声明的 JSON：哪一侧、坐标系、材料、哪个文件是哪个实体、CT 的参数、检查门的线、冒烟，都混在一起。
- STL 实体只出现在 CT 那条路的中间，不能直接当骨源。
- 检查门里的“内核冒烟”叫的是旧内核。

**谁在读骨模型**：

| 谁 | 读什么 |
| --- | --- |
| `fea.run` 的骨架（`given.py`） | 区域和标志点的名字，核名字引用 |
| M1 的柄空间包（4c） | 两个实体，按 sha256 认 3406 |
| Abaqus 的有限元包（4d） | 两个实体、五个标志点、两种材料、哪一侧 |
| 照名字引用的床支撑 F（4e） | 标志点 |
| 参照内核包 | 两个实体。它只认第 1 版的写法 |
| 重建的检查门 | 把候选交给旧内核做冒烟 |
| 优化（取候选池） | 把骨模型交给旧内核模板化（第 7 步改用柄空间包） |

各个包都是自己打开骨模型的清单读，写法一变就都读不了。

## 改成什么样

**骨模型第 2 版**（照《骨模型的写法》，这一回先做到“一块骨、三维、封闭的实体”，范围见“你定的”第 2 条）：

| 段 | 写什么 |
| --- | --- |
| 身份 | 骨标识（照旧叫 `bone_id`）、哪一侧、骨的种类（真骨、模型骨、合成的）、覆盖范围（完整的股骨，还是近端一段，多长） |
| 来源 | 怎么来的（CT 重建、CAD 导入、STL 导入）、哪个重建方法包、照哪份设定 |
| 单位和坐标 | 长度 mm、力 N、应力 MPa。几何文件用自己的坐标；另记解剖坐标系在文件坐标里的原点和三个轴，和它是照哪种定法算的（见“你定的”第 1 条） |
| 区域 | 一个或多个：名字、角色（皮质、松质、髓腔、软骨、其他）、封闭的实体（STEP 或 STL）、体积 |
| 材料 | 每个区域一种给法，和柄的模型用同一份写法（`formats/material.py`）。按骨密度给的只留位置 |
| 表面 | 用得到的命名表面，可以没有 |
| 标志点 | 每个点：值、定义（找法的名字、版本、参数）、拟合的好坏。必有的还是那五个，另可以有后髁等 |
| 检查结果、重建记录 | 照旧 |

第 1 版的骨模型照“一块骨、两个区域、均匀材料”读成第 2 版，登记过的不用重做。

**重建**：一套骨架，三个方法包。

| | 做什么 |
| --- | --- |
| 骨架（冻结） | 出候选、人看和改、定稿这三步；照第 2 版写骨模型；检查门怎么判；定稿只沿用重做不了的数 |
| 重建方法包 | CAD 导入、CT 流程、STL 导入各一个。各自声明重建设定（带测试轮的取值和来路）、能收哪种骨源、会量出哪些数 |
| 设定 | 重建设定照方法包的声明写，核心启动时照它核；检查门的线另是一份，看到结果之前写定 |

**用骨模型的一方照声明核对**：柄空间包、有限元包、推导量定义在清单里写明要骨模型的什么（哪些角色的区域、哪种几何文件、哪些材料模型、
哪些标志点、覆盖范围）。`fea.run` 启动前照它核，缺哪一样就拒，说出来。交给包的骨模型清单一律是第 2 版的样子。

## 照现在的设定定下的几处（不对就说）

1. **参照内核包只配第 1 版写法的 3406 骨模型**。它是登记后不改的旧代码，自己读清单里的 `solids`。重建以后写的是第 2 版，它读不了；
   `fea.reference` 启动前核这一条。科学验收的整条链改走新的三个包（5g）；参照包那条用手头第 1 版的 3406 骨模型照样跑。
2. **检查门里的冒烟改用柄空间包**：让柄空间包在这根骨上模板化一个设计。原来还能让内核真建一次模，这个先不做。
3. **检查门的线还是单独一份设定**，写法不变，由冻结的 `gate.py` 核。它引用的量要在方法包的清单里，不在就启动不了。
4. **“定稿只沿用重做不了的数”做成冻结的规矩**：方法包在清单里写明哪些量是定稿时重做不了的（比如 CT 那一步量的），骨架只许沿用这些。现在这条在自由代码里。
5. **骨标识照旧叫 `bone_id`**。几块骨的关节、没有骨的分析以后再说。
6. **覆盖范围必填**。区域的角色先定五种：皮质、松质、髓腔、软骨、其他。
7. **材料和柄的模型用同一份写法**（线弹性、工程常数、两种超弹性）。按骨密度给材料只在格式里留位置：蓝图写的是 1.0 不做。
8. **交给包的骨模型清单一律是第 2 版的样子**，由叫包的一方转好。包不用自己认旧版本。
9. **3406 的 CAD 骨模型内容不变**：实体还是那两个 STEP，原样用。
10. **做法照第 4 步**：每一小步一个会话；先写目标和测试；固定的部分你看过、你跑 freeze；分两次提交。

## 你定的（2026-11-19）

1. **解剖坐标系：两种定法都认，骨模型里写明用的是哪一种**。它定的是“内侧、后方”朝哪，关节力的方向照它加。
   - **有后髁的完整股骨**：干轴加后髁连线。这是 Bergmann 2016 的定法，原项目用的就是它。
   - **只有近端一段的骨**：干轴加颈轴，再照设定里写的前倾角转回去。前倾角是重建设定里必填的一项，要写来路。
   - 骨模型里记着用的是哪一种；照颈轴定的，另记前倾角取的是多少。
   - 为什么要分：两种定法绕干轴差一个前倾角。3406 上差 3.8°，设计 A 的转动、微动因此比原项目小 7% 到 11%（见《拆内核》4d）。
     成人真骨的前倾角常见在十几度上下，差得会更多。

   跟着要做的：
   - 5a：格式里写下这两种定法；从标志点算坐标系的算法放在契约里，只有一份。
     第 1 版的骨模型没有后髁的标志点，读成第 2 版时怎么写（照颈轴、没有前倾角可转），在 5a 的目标里写清。
   - 5b：有限元包加关节力时照骨模型记的解剖坐标系，不再自己从颈轴算（现在的 `load_frame`）。
   - 5d、5e、5f：方法包对完整的股骨要找出两个后髁的标志点。3406 是完整的股骨，照后髁连线定，
     定出的坐标系和原项目的模型坐标对一下，差多少列给你看。
2. **第 2 版这一回先做用得上的**：一块骨、三维、封闭的实体（STEP、STL），区域可多可少、各有角色和材料。
   壳、平面模型、现成的体网格、几块骨的关节，等真要用时再升一版：那时有包拿它们试，规矩才定得准；旧的照样读。
3. **左股骨的解剖坐标系**（做 5a 时定的）：三个轴两侧都是内侧、后方、近端，左股骨上是左手系，几何不镜像。
   怎么定的、另一种写法是什么，见 5a 的“左股骨怎么写”。

## 5a：骨模型第 2 版的格式（2026-11-19 写目标）

### 清单的写法

在 `stemlab/contract/formats/bone_model.py`，格式版本升到 2。候选骨模型和骨模型还是同一种格式。

| 段 | 清单里的项 | 写什么 |
| --- | --- | --- |
| 身份 | `bone_id`、`side` | 照旧 |
| | `bone_type` | 骨的种类：`real` 真骨；`replica` 实物的模型骨，比如 Sawbones；`synthetic` 合成的，算出来或画出来的形状，没有实物 |
| | `coverage` | 覆盖范围。`extent`：`whole` 完整的股骨，`proximal` 只有近端一段。`proximal_mm`、`distal_mm`：几何从解剖坐标系的原点沿干轴往近端、往远端各到多远 |
| 来源 | `source` | `how`：`ct`、`cad`、`stl`。`method`：重建方法包的编号和哈希。`setting`：重建设定的编号和哈希 |
| 单位和坐标 | `units` | 照旧，只有一套：mm、N、MPa |
| | `frame` | 解剖坐标系，见下一节 |
| 区域 | `regions` | 一个或多个。每个写：名字；角色；几何（封闭的实体，`step` 或 `stl`，哪个文件）；体积；材料 |
| 材料 | 区域里的 `material` | 一种给法，照 `formats/material.py`。髓腔是空的，写 null |
| 表面 | `surfaces` | 命名的表面：落在哪个区域上，哪个表面片文件。可以是空的 |
| 标志点 | `landmarks` | 每个点：`xyz`；`definition`（找法的名字、版本、参数，可以另带一句话）；`fit`（拟合的好坏：几个数） |
| 检查结果、重建记录 | `checks`、`history` | 照旧 |

- **坐标**：几何文件、标志点、表面都用文件自己的坐标，不换系。
- **区域的角色**：`cortical` 皮质、`cancellous` 松质、`canal` 髓腔、`cartilage` 软骨、`other` 其他。
- **骨的材料收哪几种**：线弹性（`elastic`）、工程常数（`engineering_constants`）、两种超弹性（`neo_hooke`、`mooney_rivlin`），
  和只留位置的按骨密度给（`density`）。分段的、按预测的场给的是柄用的，骨不收。
- **必有的标志点**还是那五个。照后髁连线定坐标系的，另要 `condyle_medial`、`condyle_lateral`：内侧、外侧股骨髁最靠后的点。
- **别的项**（比如重建写的 `measures`）照旧可以带，契约不核。

### 解剖坐标系

`frame` 记三样：几何文件自己的坐标是怎么来的（一句话，`file`）；解剖坐标系在文件坐标里的原点和三个轴；它是照哪种定法算的（`method`）。

- **三个轴**：x 指向内侧，y 指向后方，z 沿干轴指向近端。
- **z**：从 `shaft_distal` 指向 `shaft_proximal`。
- **原点**：干轴上小转子那一层，就是 `lesser_trochanter` 投到干轴上的那一点。原项目的模型坐标也是这个原点。
- **x 的两种定法**：
  - `shaft_condyles`：从 `condyle_lateral` 指向 `condyle_medial` 的连线，投到垂直干轴的面上。
    内外方向照后髁连线定，是 Bergmann 2016 的做法，原项目用的也是它。
  - `shaft_neck`：颈轴（从 `neck_center` 指向 `head_center`）投到垂直干轴的面上，再绕干轴转过 `anteversion_deg`。
    转完以后，颈轴在这个坐标系里朝前偏的角度正好是它。
- **y**：垂直于 z 和 x，指向后方。
- **前倾角**：颈轴朝前偏为正。在照后髁连线定的坐标系里量出前倾角，再拿它照颈轴定，得到的是同一个坐标系。

算法只在契约里有一份（`bone_model.frame`）。骨模型里记的原点和三个轴，核的时候照标志点重算一遍，对不上就拒：
标志点动了，坐标系要跟着重算。包不用自己算，读骨模型里记的数就行。

**哪种骨用哪种定法**（照你定的那两句写成规矩）：完整的股骨（`whole`）照后髁连线；只有近端一段的（`proximal`）照颈轴加前倾角。
两样对不上的骨模型被拒。

### 左股骨怎么写（2026-11-19 定了甲）

草案只说“左股骨怎么镜像要写明”，没有定。列给你的两种写法：

- **甲（定的是它）**：三个轴的意思两侧都一样，x 内侧、y 后方、z 近端。
  - 右股骨上这三个轴是右手系，左股骨上是左手系。骨模型里核手性和 `side` 对得上。
  - 几何不镜像，文件原样用。
  - 关节力写成（内侧、后方、近端）三个分量，两侧用同一组数、同一个算式：合力 = 三个分量各乘上对应的轴，包不用分左右。
  - 前倾角两侧同号：朝前为正。
  - 左股骨的点换到解剖坐标系里，坐标和它镜像成右股骨以后的一样。Bergmann 2016 也是把左侧的数据镜像成右侧来报的。
- **乙**：永远右手系。左股骨上 z 近端、y 后方，x 就指向外侧。
  - 好处是所有骨的坐标系都是右手系，拿它当刚体变换用不会出镜像。
  - 代价是“x 是内侧”只对右股骨成立，加关节力时每个包都要记得给左股骨的内外分量变号。

我建议的是甲：这个坐标系的用处就是告诉包内侧、后方朝哪，甲在两侧是同一句话。乙要每个包各自记得变号，漏一次就是一个不报错的反号。
现在的 Abaqus 有限元包也是照甲算的（左股骨的后方反过来叉乘）。

### 定下的几处（不对就说）

1. **原点和 z 轴照原项目的模型坐标**：原点在干轴上小转子那一层，z 是近端骨干的轴。和 Bergmann 2016 原文有两处不一样（2026-11-19 对过原文）：
   - 原文的原点在头心。原点只影响点的坐标，不影响力的方向。
   - 原文的 z 是一条直线：从股骨中线和颈轴的交点，到髁间窝的中点。它和近端骨干的轴差一个小角度，差多少没量过。
     要严格照原文，得再加一个标志点（髁间窝的中点），这一回没做；原项目也没这样做。
   - 原文的 x 指向外侧、y 指向前方；这里是 x 内侧、y 后方，和原项目一样。两个分量换过去要变号，原项目的配置里已经是换好的。
2. **哪种骨用哪种定法**写成了规矩，见上面。
3. **骨的种类**的三个名字：`real`、`replica`、`synthetic`。模型骨没有用 `model` 这个词，它在代码里已经有两个意思（骨模型、材料模型）。
4. **覆盖范围多长**记成从原点往近端、往远端各到多远。柄空间包要“到小转子下至少多少”，直接和 `distal_mm` 比。
5. **`frame.file`**：文件自己的坐标是怎么来的，一句话，必写。第 1 版的四句话有地方放。
6. **名字**：区域、表面、标志点的名字都用小写字母、数字和下划线，和第 1 版的标志点一样。名字引用里用点分段，名字里不能有点。
7. **髓腔不写材料**，别的角色都要写。
8. **照后髁连线定的时候**，定出的内侧要和颈轴指的大致同向（量出的前倾角在 ±90° 以内），不然就是内外两个后髁写反了，拒。

### 启动前核什么（冻结的 `plugin.py`、`gate.py`）

两种实验都核：
1. 方法包会这一种：清单的 `modes` 里有 `draft`（出候选）或 `finalize`（定稿）。
2. 方法包的清单：`outputs` 是它会量出的数，role 都写 `label`；不能用骨架自己记的三个名字（`stem_smoke`、`stem_smoke_reason`、`anteversion_deg`）；
   `kept` 只能写 `outputs` 里的名字。
3. 重建设定照声明写（老写法的拒），照的是这个方法包的 `rebuild`；不能有每个点给的项：重建没有一批点。
   取值对不对由核心照声明核（第 1 到 5、7、9 条，原来就有）。
4. 检查门的线写得对（原来的几条照旧），每条拿来比的量是方法包 `outputs` 里的，或是骨架自己记的那三个。不是的拒，说出是第几条、哪个量。

6. 检查门里有冒烟（有一条拿 `stem_smoke` 来比）：要填柄空间包，它要会 `template`；要填放置设定，照这个柄空间包的 `placement` 声明写；

   检查门里没有冒烟，柄空间包、放置设定都不该填。
7. 人工修改写得对不对，照旧由自由代码核（`review.py`）。
