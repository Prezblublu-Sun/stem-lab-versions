# stem-lab 1.0 蓝图

Nov 13, 2026 · @Prez

stem-lab 1.0 是一套管实验的系统。它把股骨重建、FEA、代理、优化四类计算接到同一本账上，让每个结果都追得到它用的骨、点、代码和轮次。这份蓝图是开工的依据：按它建目录、写测试、写代码。

## 五条原则

整套设计由这五条推出。拿不准一段代码该不该写、该放哪，回到这里判断。

1. **只存三样。** 登记链、实验记录链、发布后只读的产物文件夹。状态、关系、图表都由它们算出来，不另存。
2. **只有一个写入者。** 两条链只由 Windows 上的操作台核心写。Linux 那台和所有插件都不写。
3. **插件只交候选。** 插件算出文件，交给核心。核对、算哈希、给编号、登记都由核心做，所以插件怎么重写都改不了任何东西的身份。
4. **规则只有一份。** 什么算合法的记录、现在是什么状态、此刻能做什么，都是契约里的纯函数。各块问的是同一份。
5. **固定的小，自由的大。** 契约和核心合计约 3600 行，有设计地写、逐行看。插件里怎么算、界面、仪表盘可以随便重写，由测试守着。

1.0 是全新写的，不以任何已有代码的行为为基准。已有的内核、数据、骨模型要用，就和别的外来东西一样登记进来。

## 存什么

### 登记的东西

实验用到和产出的每样东西都有一条登记。登记后不改不删；同名再登记，版本加一，编号是新的。

| 字段 | 含义 |
| --- | --- |
| `id` | 编号。骨这一层的（case）以 C 开头，其余以 R 开头。由登记的条数得出，不重用 |
| `kind` | 种类，见下表 |
| `name`、`version` | 名字和版本。实验的产物自动叫 `E0007.data` 这样的名字 |
| `storage` | 存法：`value` 一个值；`copy` 复制一份进 `data/`；`ref` 只记位置 |
| `content` | 值，或者文件夹的位置 |
| `hash` | 完整的 SHA-256，一律按字节算 |
| `origin` | 来路，只有两种形状 |
| `bone_id` | 骨标识。同一根骨的所有版本共用 |
| `time`、`format` | 登记时间；这条记录的格式版本 |

来路的两种形状，别的登记不上：

```
{"from": "external", "note": "...", "by": "..."}
{"from": "product", "experiment": "E0007", "round": 2, "output": "data"}
```

骨标识在登记骨源时由你给，骨模型继承它。一批点里的“骨”、数据的每一行、预测器的适用范围，写的都是骨标识。登记一个没见过的骨标识要明说是新骨，防打错字。

种类一共十六种，按形态分四组：

| 形态 | 种类 | 代码里的名字 | 说明 |
| --- | --- | --- | --- |
| 文件夹 | 骨源 | `bone_source` | case。CT 或 CAD |
| 文件夹 | 骨模型 | `bone_model` | case。两个实体、标志点、材料、单位和坐标系 |
| 文件夹 | 候选骨模型 | `bone_draft` | 等人工检查的重建结果，不算 case |
| 文件夹 | 人工修改 | `edits` | 你改过的文件和改了哪里 |
| 文件夹 | 归档清单 | `archive` | FEA 原始结果的位置和每个文件的哈希 |
| 文件夹 | 报告 | `report` | 待检查清单、检查结果、误差报告、复核报告、判定结果 |
| 表 | 一批点 | `points` | 每个点：名字、骨标识、设计、写全的条件、理由 |
| 表 | 候选池 | `pool` | 模板化过、知道可不可行的一大批设计 |
| 表 | 数据 | `data` | FEA 的结果。每行带点的哈希、骨标识、轮号、输入指纹、结局 |
| 表 | 一份预测 | `prediction` | 列和数据同名，另加不确定度 |
| 带代码的包 | 内核 | `kernel` | 建模的代码 |
| 带代码的包 | 策略 | `strategy` | 选点的代码 |
| 带代码的包 | 推导量定义 | `derive_def` | 从场算指标的代码 |
| 带代码的包 | 预测器 | `predictor` | 训练好的模型加推理代码，带适用范围 |
| 值 | 目标和约束 | `objective` | 优化什么，什么算可行 |
| 值 | 设定 | `setting` | 重建设定、导出设定、训练设定、划分、条件默认、判据、设计范围 |

四条通则：

- 文件夹形态的东西都带一份 `manifest.json`。契约只核清单；内容和清单对不对得上，由写它的那个冻结文件负责。
- 四种带代码的包是同一种格式：清单、`code/`、`data/`、入口、依赖、一组自检样本。包不 import `plugins`，所以插件重写之后旧的包照样能跑。
- 一批点登记时条件必须写全。手写的可以指定一份条件默认，核心补全之后再存。每个点的哈希由骨标识、设计、写全的条件算出。
- 落盘的名字和 JSON 的键一律用 ASCII，中文名只用于显示。

### 实验、轮、任务

| 层 | 是什么 | 什么时候定下来 |
| --- | --- | --- |
| 实验 | 一种类型加一份输入 | 第一次启动时输入存定，之后不变 |
| 轮 | 照这份输入跑的一次 | 每次启动开新的一轮。旧轮的记录和产物一条不动 |
| 任务 | 一轮里的一个作业 | FEA 一个点一个任务；一次训练一个任务 |

- 东西之间的关系不存。由两处算出：登记里的来路，和实验存定的输入。
- 追溯有两条线。产物的来路说的是哪一轮发布的；数据每一行的轮号说的是哪一轮算的。问“这一行是哪份代码算的”，走行上的轮号。
- 输入指纹是一个 FEA 作业的身份：点的哈希、骨模型的哈希、内核的哈希、导出设定的哈希、插件冻结文件的哈希，合起来再算一次。

### 记录的条目

一个实验一份只追加的记录，一共十二种条目。每条都带格式版本、序号、上一条的哈希、时间；开轮之后的还带轮号。

| 条目 | 什么时候写 | 带什么 |
| --- | --- | --- |
| `created` | 新建 | 类型；这个类型的输入表、产物表、结局表；说明、标签 |
| `filled` | 填一样输入 | 输入名、登记的编号 |
| `frozen` | 第一次启动 | 每样输入的编号、种类、版本、哈希、来路；登记当时的链头 |
| `round_opened` | 每次启动 | 轮号、这一轮的来历、要重排的任务 |
| `called` | 叫完插件的启动或停止 | 哪个动作，成了还是出错 |
| `task` | 任务的状态变了 | 任务、状态、结局名、阶段、机器、输入指纹 |
| `output` | 发布了一样产物 | 产物名、登记的编号、哈希 |
| `problem` | 出了问题 | 报错、任务、原始报错。同一个报错连着出现只记一次，结束时记次数 |
| `provenance` | 插件或远端补来历 | 求解器版本、远端的环境、用到的包 |
| `round_closed` | 一轮结束 | 结局和原因 |
| `noted`、`tagged` | 随时 | 备注；标签的增减 |

把输入表、产物表、结局表抄进 `created`，是为了插件拔掉或改了之后，旧实验照样读得懂。

每一轮必记的来历，由核心记，不靠插件自己报：

- 本机：核心的提交号、契约和核心是否干净、`FROZEN` 清单的哈希、插件文件夹的哈希、插件没提交的改动（存成文件）、契约版本、Python 版本、锁文件的哈希、主机名。
- 在远端跑的轮再加：远端的主机名、Python 和关键库的版本、CUDA 和驱动、GPU 型号。
- 用到带代码的包时再加：包的编号和哈希。

## 状态

### 实验的状态

四种：未启动 `new`、启动中 `starting`、运行中 `running`、已结束 `ended`。实验的状态就是它最后一轮的状态，由记录重放得出，不另存。下面这张表是契约里的一份数据，表里没有的组合一律拒绝。

| 操作 | 什么状态时能做 | 写下什么 | 之后的状态 |
| --- | --- | --- | --- |
| 新建 | 随时 | `created` | 未启动 |
| 填输入 | 未启动 | `filled` | 未启动 |
| 启动 | 未启动；或已结束，且结局不是做完或有可以重排的任务 | 第一次先写 `frozen`，然后 `round_opened` | 启动中 |
| 核心记：启动成了 | 启动中 | `called` | 运行中 |
| 核心记：启动出错，或持锁的进程不在了 | 启动中 | `called`、`round_closed` | 已结束，结局是启动失败 |
| 停止 | 运行中，且这个类型写了停止 | 插件停成了才写 `called`、`round_closed` | 已结束，结局是停止 |
| 插件说做完 | 运行中 | `round_closed` | 已结束，结局是做完 |
| 插件说做不下去 | 运行中 | `round_closed` | 已结束，结局是失败 |
| 报任务、交产物、报问题、补来历 | 启动中、运行中 | `task`、`output`、`problem`、`provenance` | 不变 |
| 克隆 | 随时 | 另一个实验的 `created` 和 `filled` | 新实验是未启动 |
| 备注、标签 | 随时 | `noted`、`tagged` | 不变 |

四条规则：

- **状态只在“结果”上变。** 停止要等插件真的停成了才生效。没停成，实验还是运行中，多一条问题，可以再停一次。所以插件的停止必须可以重复叫。
- **没有暂停。** 停止之后再启动，新的一轮只重排没做完的任务，效果就是暂停再继续。
- **启动卡死由你结束进程。** 值守发现持锁的进程不在了，把这一轮记成启动失败。
- **类型没写停止就不能停。** 它自己会结束。

轮的结局四种：做完 `done`、失败 `failed`、停止 `stopped`、启动失败 `start_failed`。做完不等于每个任务都成功，失败了几个写在旁边。

### 任务的状态和结局

任务五种状态：排队 `queued`、运行 `running`、完成 `done`、失败 `failed`、停止 `stopped`。完成和失败都带一个结局名。结局名由类型声明，每个名字属于下面四类之一。

| 类别 | 任务状态 | 含义 | 再启动时 | 进不进数据 |
| --- | --- | --- | --- | --- |
| 算出来了 `ok` | 完成 | 正常的结果 | 不重排 | 进 |
| 结论 `conclusion` | 完成 | 这个点就是这个结果，再算也一样 | 不重排 | 进，带结局名。优化把它当不可行的证据 |
| 可重试 `retryable` | 失败 | 和点无关的偶发问题 | 自动重排 | 不进 |
| 待查 `unclear` | 失败 | 说不清，先当失败 | 你点名才重排 | 不进 |

可以重排的任务，指排队的、停止的、可重试的，加上你点名的待查的。

## 写入

### 往链上追加一条

两条链各只有一个追加的函数，步骤相同：

1. 拿这条链的锁。
2. 末尾如果是写了一半的一行，截掉。
3. 读链头，给新条目序号和上一条的哈希。
4. 实验记录多一步：由全部条目算出现状，问状态表这一条现在能不能记。
5. 按字节追加一行，UTF-8、LF，然后落盘。
6. 放锁。

### 四把锁

| 锁 | 护什么 | 说明 |
| --- | --- | --- |
| `register.lock` | 登记链的追加 | 操作系统的文件锁，进程死了自动释放 |
| `record.lock`，每个实验一把 | 这个实验记录的追加 | 同上 |
| `busy.lock`，每个实验一把 | 同一个实验同一时刻只有一处在动 | 启动、停止、值守都先拿它。里面记着持锁进程的进程号和创建时间 |
| `watch.lock` | 同一时刻只有一处在值守 | 同上 |

顺序固定：`busy` 在最外；两条链的锁不嵌套；叫插件代码的时候不拿链的锁。锁的都是单独的 `.lock` 文件，不锁链文件本身。

### 启动的九步

前五步只检查，什么都不写。任何一步不过就拒绝，记录里不多一条。

| 步 | 做什么 | 不过的话 |
| --- | --- | --- |
| 1 | 状态表允许启动 | 拒绝 |
| 2 | 必须的输入都填了。看 `created` 里抄下的输入表 | 拒绝，说出缺哪几样 |
| 3 | 每样输入种类对，哈希和登记时一致。第一轮算出的哈希就是存定用的那一个；之后的轮要和存定的一致 | 拒绝，说出是哪一样 |
| 4 | 代码的状态：`FROZEN` 清单对得上；契约和核心没有没提交的改动；不是第一轮时，`FROZEN` 清单的哈希和上一轮相同 | 拒绝，说出是哪个文件 |
| 5 | 叫插件的检查。检查里只能读 | 拒绝，原因原样给你 |
| 6 | 第一轮：记 `frozen` |  |
| 7 | 记 `round_opened`：轮号、来历、要重排的任务。插件有没提交的改动就把差异存成文件。状态变成启动中 |  |
| 8 | 叫插件的启动 |  |
| 9 | 记 `called` | 成了：运行中。出错：再记 `round_closed`，结局是启动失败 |

插件带着没提交的改动可以启动，来历里写明不干净，差异留在这一轮的文件夹里。契约、核心、插件的冻结文件有改动则不行。

### 值守

值守每隔一段时间看一遍所有运行中的实验。对每个实验：拿 `busy`，叫插件的轮询，插件借这次调用报任务、交产物、报问题、说做完；然后对一次账。启动中而持锁进程不在了的，记成启动失败。连不上远端时退避重试，不记成任务失败。

### 发布一样产物的六步

插件把算好的文件夹放在自己的 `work/` 里，说一声“交这一样产物”。下面六步都由核心做，每一步都能重做，所以断在哪一步都接得上。

| 步 | 做什么 | 不过，或者断在这一步之后 |
| --- | --- | --- |
| 1 | 产物名在这个类型的产物表里，种类相符 | 拒绝，记成问题。文件留在原地 |
| 2 | 按契约核对清单 | 拒绝，记成问题，说出哪里不符 |
| 3 | 移进 `rounds/轮号/outputs/产物名/`，算每个文件的哈希 | 对账时看到没登记的产物文件夹，从第 4 步接着做 |
| 4 | 设成只读 | 同上 |
| 5 | 登记。来路是这个实验的这一轮 | 登记里有、记录里没有。对账时补第 6 步 |
| 6 | 记一条 `output` |  |

对账做两遍和做一遍结果相同。值守每看一遍顺带对一次，`检查` 命令里也有。

### 备份

备份把 `data/` 每周一次推到 Linux 那台，并把两条链当时的链头记进 `backup.json`。产物只读、链只追加，所以每次只用传新增的部分。它同时管两件事：

- **恢复。** 核对只能发现问题，恢复靠备份。Linux 上也能跑同一套核对。
- **发现末尾被删。** 哈希链查得出中间被改，查不出最后几条被删。`检查` 会核对本机的链是不是上次备份那一份的延长。

## 八种实验类型

四个插件一共报八种类型。一个实验就是其中一种类型跑在一份存定的输入上。

图上只是可能的前后关系，不是规定的顺序：每一样输入也都可以是外面拿来登记的。闭环的最后一步是复核：把预测和后来的 FEA 结果按点的哈希对齐，看代理推荐的方案实际表现如何。

| 类型 | 输入（括号里是可选的） | 任务 | 产物 | 结局名和类别 | 在哪跑 |
| --- | --- | --- | --- | --- | --- |
| `recon.draft` | 骨源；重建设定 | 一个：导入、自动重建 | 候选骨模型；报告（待检查清单） | 重建完：算出来了。重建出错：待查。环境问题：可重试 | Windows |
| `recon.finalize` | 候选骨模型；重建设定；（人工修改）；（内核，做建模冒烟） | 一个：用上修改、转成两个实体、过检查门 | 骨模型，继承骨标识；报告（检查结果） | 过了：算出来了。没过检查门：结论，不交骨模型。环境问题：可重试 | Windows |
| `opt.pool` | 骨模型；内核；设计范围 | 一个：批量模板化，不做 FE | 候选池 | 生成完：算出来了。环境问题：可重试 | Windows |

| `fea.run` | 骨模型；一批点；内核；推导量定义；导出设定；（判据） | 每个点一个：建模、求解、后处理 | 数据；归档清单；填了判据时加报告（判定结果） | 算完：算出来了。放不进去：结论。不收敛、网格失败：待查。环境问题：可重试 | Windows，本机的独立进程 |

| `surrogate.predict` | 预测器；一批点 | 一个：出预测 | 一份预测 | 出完：算出来了。环境问题：可重试 | Windows |
| `surrogate.check` | 一份预测；数据 | 一个：按点的哈希对齐、算差 | 报告（复核报告） | 复核完：算出来了。一个点都对不上：结论 | Windows |

六条约定：

- 每个类型的输入表、产物表、结局表都是写死的。要不同的输入或产物，就是另一种类型。
- 一样输入可以声明收哪几种、收一份还是多份。
- 人工检查放在两个实验之间。`recon.draft` 出候选；你在系统外看和改，把修改登记进来；`recon.finalize` 定稿。输入存定后不能改这条规矩不开例外。
- 收口也是 `opt.select`，换一份收口用的策略，产物还是一批点。
- 批量选点用的模型可以由策略用已有数据在内部拟合，登记的预测器是可选输入。理由里写明用的是哪一个。
- “不收敛”和“网格失败”先归待查。它们算不算结论是科学判断，由你定。

读完这一个包，就知道任何一条历史数据怎么读、任何一个操作此刻能不能做。里面全是定义和纯函数，只用标准库，不 import 别的块。约 900 行。

守住三条：

- 除了 `hash_file`、`hash_tree`、`read_points` 读文件，不碰盘。

- 读到比自己新的格式版本，说出来，不当成坏数据。

怎样算做对（`tests/contract/`）：

1. 状态表：每种操作在每种状态下都有明确的答案，逐格试过。
2. `fold`：同一串条目重放两遍结果相同；每种条目缺一项必填的都被拒。
3. 同样的内容在 Windows 和 Linux 上算出同一个哈希；文件的先后不影响 `hash_tree`。
4. 一批点：写出再读回不变；条件没写全的被点名；补默认两次结果相同，已经写了的不被改；同一个点哈希相同，改任何一项就变。
5. 来路只认两种形状。
6. 每种格式有好样本和坏样本，坏的被点名哪里不符。

## 核心四块

四块合计约 2700 行。每块给一句目标、文件、要守住的几条、怎样算做对。每块的验收就是 `tests/blocks/` 里对应那一份测试的目录。

### 登记 `stemlab/registry/`

一样东西登记之后，编号、哈希、来路永远答得出，谁也改不了。约 450 行。

| 文件 | 里面有什么 |
| --- | --- |
| `lock.py` | `writing()`：登记链的锁 |
| `reader.py` | 读两个 jsonl 的唯一一处，容忍末尾半行；`head()` 链头 |
| `lookup.py` | `get(编号)`、`find(种类, 名字)`、`latest(名字)`、`cases()`、`bone(骨标识)`、`content(编号)`、`by_origin(实验, 轮)`、`attached(case)` |
| `verify.py` | `verify_register()` 链有没有被改；`verify_item(编号)` 内容和登记时还一不一致，返回算出的哈希；`verify_refs()` 把只记位置的全核一遍 |
| `register.py` | `register_external(...)`、`register_output(...)`；唯一的追加函数；复制内容、设成只读 |
| `links.py` | `attach(编号, case)`、`detach(编号, case)`：手动把一样东西挂到某个 case 下面。只影响在哪里看得到，不是来路 |

守住：

- 读的三个文件不 import 写的两个。
- `register_output` 只收发布算好的哈希，只许 `hooks/publish.py` 叫。

怎样算做对：

1. 登记一个外来的文件夹（复制）：各字段都记下；原件之后改了，存下的那一份不变。
2. 只记位置的，原件改了：`verify_item` 不过，并说出是哪一样。
3. 同名再登记：版本加一，编号是新的，旧版本还在；同名换种类被拒。
4. 清单外的种类、形状不对的来路、没给骨标识的 case、条件没写全的一批点，都登记不上。
5. 手改或手删一条：`verify_register` 指出是哪一条。
6. 四个进程同时登记：编号不重复，链接得上。
7. 末尾留着半行：读不崩，下一次追加前被截掉。

### 实验记录 `stemlab/experiments/`

实验的现状只由记录重放得出，没有第二份状态。约 350 行。

| 文件 | 里面有什么 |
| --- | --- |
| `lock.py` | `writing(实验)`：这个实验记录的锁；`issuing()`：发号的锁 |
| `reader.py` | `read(实验)`、`head(实验)`、`verify(实验)`、`all_ids()` |
| `log.py` | `create(类型, 三张表, 说明, 标签)` 发号并写第一条；`append(实验, 条目)` |
| `view.py` | `view(实验)` 现状：状态、输入、轮、任务、产物、问题；`rounds(实验)`；`required(实验)` 还缺哪几样输入；`summary(实验)` 一行摘要 |

守住：

- `append` 就是“写入”一节的六步。这一块里不出现对状态名的判断。
- `view` 不往盘上存缓存。
- 编号用过不再用，文件夹被删了也一样。

怎样算做对：

1. 状态表逐格：能做的记得上，不能做的记录里不多一条。
2. 同一样输入填两次：现状以后一次为准，两次都留在记录里；存定之后再填被拒。
3. 把插件拔掉：`required` 照样答得出缺哪几样。
4. 再启动：旧轮的条目一条不动，新条目都带新的轮号。
5. 四个进程同时追加：一条不少，都接得上。
6. 手改或手删一条：`verify` 指出是哪一条。

### 挂点 `stemlab/hooks/`

插件写得再糟，最坏的结果是这个实验多一条问题。约 1000 行。

| 文件 | 里面有什么 |
| --- | --- |
| `__init__.py` | 门面，插件能用的全部名字：`Kind`、`Input`、`Output`、`Outcome`、`Chart`、`TASK_STATES`、`read_points`、`write_points`、`check_format`、`fingerprint`、`predict`、`derive`、`run_strategy`、`run_kernel`、`spawn`、`alive`、`remote`。只转出，不写逻辑 |
| `load.py` | `load()` 找到所有插件，返回类型名到 `Kind` 的表；装不上的给出原因，别的照常；`plugin_hash`、`frozen_hash` |
| `handle.py` | 一次调用里插件能做的事，清单见“四个插件”一节。检查和图表拿到的是只读的那一份 |
| `call.py` | `call(类型, 动作, 实验)`：唯一叫插件代码的地方。出错不往外抛，记成这个实验的问题；同一个报错连着出现只记一次。`call_check`、`call_chart` |
| `publish.py` | `publish(...)` 六步，每步一个可以重做的小函数；`reconcile(实验)` |
| `entry.py` | `run(包的编号, 输入文件夹)`：在子进程里跑一个带代码的包。跑之前核哈希；第一次在这台机器上用，先过自检样本；用了哪个包记进来历。`predict`、`derive`、`run_strategy`、`run_kernel` 是它的四个薄封装 |
| `local.py` | `spawn(命令)` 起一个脱离父进程的本机进程，返回进程号和创建时间；`alive(进程)`；`kill(进程)` |
| `remote.py` | `push`、`start`、`status`、`pull` 四个动作；`snapshot(插件)` 打代码快照。见“两台机器”一节 |

守住：

- `stemlab/` 里不出现任何插件或类型的名字。插件靠扫描 `plugins/` 找到。
- `handle` 只在一次调用里有效。脱离出去的进程和远端的 worker 都拿不到它。
- 叫插件代码的时候不拿链的锁。

怎样算做对：

1. 一个类型报的三张表和它写了哪几个动作，都读得出。
2. 检查里往记录写：被拒，记录里不多一条。
3. 动作抛错：记成问题，不往外抛，别的实验照常。
4. 同一个报错连着三次：只有一条问题，恢复时写明三次。
5. 一个插件装不上：别的照常，它的旧实验照样能看。
6. 发布：产物表里没有的、种类不符的、清单不符的，各被拒并记成问题，文件留在原地。
7. 在发布的每一步之后掐断，再对账：没有登记了一半的产物；对账两遍和一遍一样。
8. 只记位置的输入在启动之后被改了：不交出内容，记成问题。
9. 包：哈希不符不跑；自检不过不交出结果；包崩了不带倒值守。
10. 坏插件的七样都扛得住，见“守边界”一节。

### 操作台核心 `stemlab/desk/core/`

你的每个动作都是“查状态表、记、叫、记结果”，断在哪一步都留下读得懂的记录。约 900 行。

| 文件 | 里面有什么 |
| --- | --- |
| `desk/__main__.py` | 入口，只转调。`python -m stemlab.desk ...` 进界面的命令行 |
| `core/actions.py` | `register`、`attach`、`detach`、`new`、`clone`、`fill`、`fill_new`、`note`、`tag` |
| `core/start.py` | `start(实验, 点名重排的任务)` 九步；`stop(实验)`；`poll(实验)` 叫一次轮询 |
| `core/query.py` | 只读。`under_case(case)` 这个 case 下面有什么，每样写着原因：直接用了、经别的产物用了、是它的产物、手动挂的。`upstream(编号)`、`downstream(编号)`、`same_bone(骨标识)`、`charts(实验)`、`chart(实验, 图表名)` |
| `core/watch.py` | `once()` 看一遍；`run(间隔)` 一直值守；`status()` |
| `core/check.py` | `verify_all()`、`reconcile_all()`、`check_backup()`、`guard()`。它是检查的固定入口：`python -m stemlab.desk.core.check` |
| `core/backup.py` | `backup(机器)` |
| `core/code_state.py` | `snapshot(插件)` 这一轮的来历；`frozen_ok()`；`clean(路径)` 只看声明的路径干不干净 |
| `core/locks.py` | `busy(实验)`、`watch_lock()` |

守住：

- 登记和实验记录互不相用，`query.py` 是两边唯一的汇合处。
- 只有 `start.py` 叫插件的启动、停止、轮询。
- 检查的入口在核心里，不在界面里。界面重写时漏不掉任何一项检查。

怎样算做对：

1. 登记、新建、填、启动、值守、看：用示范插件走通一遍。
2. 缺输入、种类不对、登记的东西被改过、检查不过、`FROZEN` 对不上、核心不干净：启动被拒，说出原因，记录里什么都没多。
3. 插件不干净：能启动，来历里写着，差异存下了。
4. 存定的哈希就是核对时算的那一次，没有算第二次。
5. 在启动的每一步之后掐断：值守下一遍把它收成启动失败，记录读得懂。
6. 两处同时启动同一个实验：插件的启动只被叫一次。
7. 停止没停成：状态还是运行中；再停一次能成。
8. 再启动：只重排该重排的任务；一个都没有且结局是做完时被拒。
9. 克隆：新实验的输入逐样相同，旧实验一条不变。
10. 往上追一批点：追得到选它的实验、那一轮、用的策略和目标；手写的追到“外面拿来的”为止。
11. 值守开着，不点任何东西，任务自己走完；同一时刻只有一处在值守。
12. 删掉登记的最后两条：`check_backup` 报出来。

## 四个插件

### 共同的骨架

四个插件用同一个骨架，按同一个顺序写：`plugin.py`，冻结文件和它们的测试，用假的计算走通一遍，最后才写真的自由代码。

```
plugins/<名>/
  plugin.py     冻结：KINDS = [...]，每个类型的输入表、产物表、结局表、图表、动作
  ...           冻结：别人依赖的格式和规则
  ...           自由：怎么算
  worker.py     自由：在远端跑的入口，只有代理需要
  charts.py     展示：给图表的数据
  tests/        自由代码自己的单元测试，不进 FROZEN
```

插件只 import `stemlab.hooks`。冻结文件一共 15 个：重建 3、FEA 5、代理 4、优化 3。

### 四个动作

| 动作 | 什么时候被叫 | 约定 |
| --- | --- | --- |
| `check(handle)` | 启动的第 5 步 | 只读。说过或不过，不过要给原因 |
| `start(handle)` | 每一轮开头 | 把这一轮要跑的任务派出去就返回，不等它们跑完。`handle.round` 说这是第几轮、要重排哪些任务 |
| `poll(handle)` | 值守每看一遍 | 看活干到哪了：报任务、交产物、报问题；都完了就说做完或做不下去。可以重复叫 |
| `stop(handle)` | 你点停止 | 把在跑的停掉，已经算好的可以照常交。可以重复叫。这个动作可以不写 |

- 动作必须很快返回。长时间的活放到脱离出去的本机进程（`spawn`）或远端（`remote`），下一次 `poll` 再去看。
- 动作在操作台的进程里跑。卡死了由你结束进程。

### handle：一次调用里能做的事

| 读写 | 能做什么 |
| --- | --- |
| 读 | `input(名字)` 一样输入的内容或位置，只记位置的先再核一次哈希；`input_info(名字)` 编号、种类、版本、哈希、骨标识；`round` 轮号和要重排的任务；`tasks()` 各任务现在的状态；`work_dir` 自己的文件夹 |
| 写 | `task(任务, 状态, 结局名, 阶段, 机器, 输入指纹)`；`output(产物名, 文件夹)` 交一样候选的产物；`problem(报错, 任务, 原始报错)`；`provenance(各项)`；`finish()`；`fail(原因)` |

检查和图表拿到的 `handle` 只有读的那一行。

### 重建 `plugins/recon/`

一根骨从骨源到过了检查门的骨模型，每处人工改动都留痕。

| 文件 | 层 | 里面有什么 |
| --- | --- | --- |
| `plugin.py` | 冻结 | `recon.draft`、`recon.finalize` 两个类型 |
| `gate.py` | 冻结 | 检查门：网格检查；填了内核就经 `run_kernel` 做一次建模冒烟。过不过的线从重建设定里读，不写在代码里 |
| `model.py` | 冻结 | 按骨模型格式写出候选和定稿；骨标识从骨源继承 |
| `sources.py` | 自由 | 认出是 CT 还是 CAD，读进来 |
| `rebuild.py` | 自由 | 自动重建：分骨、外表面、内壁，出皮质和松质两个面 |
| `landmarks.py` | 自由 | 找标志点。有哪几个、在什么坐标系里，由格式定 |
| `review.py` | 自由 | 待检查清单，把不可靠的地方标出来；用上人工修改并记下改了哪里 |
| `solids.py` | 自由 | 转成 FEA 要的两个实体 |
| `charts.py` | 展示 | 各步用时、网格质量分布、截面预览、待检查清单 |

怎样算做对：

1. 一份 CAD 骨源走完两个类型：骨模型过格式核对，骨标识、两个实体、标志点、材料、单位、坐标系、重建记录、检查结果都在。
2. 没过检查门：结局是“没过检查门”，不交骨模型，报告里写着哪一项没过。
3. 填了人工修改：骨模型里记着改了哪里。
4. 把 `rebuild.py` 整个换一份写法：格式核对和检查门照过，或者如实不过。
5. 人工·科学：一根你核过的骨，标志点和你标的差多少；两个实体的体积、皮质厚度落在合理范围里。线和范围由你定。

### FEA `plugins/fea/`

给定骨模型、设计、条件，算出力学响应；每一行数据都追得到点、骨、轮。

| 文件 | 层 | 里面有什么 |
| --- | --- | --- |
| `plugin.py` | 冻结 | `fea.run` 一个类型 |
| `outcomes.py` | 冻结 | 一个作业结束后归到哪个结局名 |
| `export.py` | 冻结 | 从作业的结果导出数据：标签、界面场、整体场，推导量经 `derive` 算。写数据说明：每列的名字、单位、含义。每行带点的哈希、骨标识、轮号、输入指纹、结局 |
| `archive.py` | 冻结 | 一个作业留下什么：网格、每一步的场、求解过程、求解设置。失败前算出来的步也留。写归档清单 |
| `judge.py` | 冻结 | 按判据判定。判据的登记时间晚于这一轮开始的被拒 |
| `jobs.py` | 自由 | 一个点一个作业；算输入指纹；核对点里的骨标识和骨模型一致、点的条件项和内核要的一致 |
| `run.py` | 自由 | 经 `run_kernel` 建模，经 `spawn` 起求解进程，按求解槽数排队；看每个作业走到哪：排队、建模、求解、后处理 |
| `charts.py` | 展示 | 作业走到哪、一个作业的求解过程、已算完的点、失败原因 |

怎样算做对：

1. 三个点的一批点：三个任务，各走完阶段。用假的求解。
2. 一个作业不收敛：记成待查，别的作业照常；失败前算出来的步也在归档里。
3. 放不进去的点：任务是完成，结局是放不进去，数据里有这一行。
4. 点里的骨标识和骨模型不一致，或条件项和内核要的不一致：检查不过。
5. 数据的每一行带齐五样键；数据说明里每列有单位。
6. 再启动：只重排该重排的；新一轮的数据里，每行写着是哪一轮算的。
7. 把 `jobs.py` 和 `run.py` 整个换一份写法：上面几条照过。
8. 人工·科学：一个有解析解或独立算过的小算例在容差内；反力和外载平衡；单位和坐标系对。算例和容差由你定。

### 代理 `plugins/surrogate/`

换模型不换评价：划分、误差算法、预测器格式不随模型变。

| 文件 | 层 | 里面有什么 |
| --- | --- | --- |
| `plugin.py` | 冻结 | `surrogate.train`、`surrogate.predict`、`surrogate.check` 三个类型 |
| `split.py` | 冻结 | 照登记的划分切成训练和留出。留出的行一行都不进训练；按骨分时，留出的骨标识不出现在训练里 |

| `predictor.py` | 冻结 | 把模型打成包：权重和设备无关、不存路径对象、推理代码放进包里、带自检样本和适用范围；`in_range(点)` |
| `data.py` | 自由 | 读数据，照数据说明认出骨、设计、条件、预测量各是哪几列；几份数据里同一个点结果不同的说出来 |
| `features.py` | 自由 | 特征。只用不做 FE 就拿得到的量 |
| `models/` | 自由 | 标量的和场的预测器，各有训练和预测。给均值和不确定度 |
| `train.py` | 自由 | 一次训练。种子从训练设定里读 |
| `worker.py` | 自由 | 在 Linux 上跑的入口：读输入、训练、打包、写状态文件 |
| `predict.py` | 自由 | 对一批点出预测。超出适用范围的点不出数、记一条问题，别的点照常 |
| `charts.py` | 展示 | 训练过程、留出上预测对真值、各预测量的误差、复核的散点 |

怎样算做对：

1. 留出的行一行都没进训练；按骨划分时，留出的骨一根都没进。
2. 特征里没有 FE 算出来的列。
3. 同样的输入和种子再训练一次：误差报告在容差内相同。
4. 预测器在 Linux 上打包、在 Windows 上加载：自检过，两边的预测在容差内相同。
5. 把 `models/` 整个换成另一种模型：冻结的四个文件不用改，测试照过；换之前打的包照样出同样的预测。
6. 登记一个外面训练好的预测器，不训练直接出预测。
7. 复核：预测和数据对得上的点逐个有差值；对不上的点列出来。
8. 人工·科学：留出误差多大算可用，线由你定，并在结果出来之前登记。

### 优化 `plugins/opt/`

选点可重放，可行性不靠策略自觉。

| 文件 | 层 | 里面有什么 |
| --- | --- | --- |
| `plugin.py` | 冻结 | `opt.pool`、`opt.select` 两个类型 |
| `feasible.py` | 冻结 | 不满足约束的点不出现在一批点里，和用哪份策略无关 |
| `replay.py` | 冻结 | 记下策略的编号、种子、每样输入的编号；`replay(实验, 轮)` 拿这些重放出同一批点 |
| `pool.py` | 自由 | 在设计范围里取设计，经 `run_kernel` 做模板化，记下每个设计可不可行 |
| `inputs.py` | 自由 | 读各样输入，核对它们对得上：同一个骨标识、同一版目标 |
| `select.py` | 自由 | 一次选点：经 `run_strategy` 跑策略，过可行性，写理由，补全条件，经 `write_points` 写出 |
| `reasons.py` | 自由 | 每个点的理由：哪个策略、分数、用的模型（登记的预测器，或策略内部的）、哪版目标、哪几份数据 |

2. 同样的输入和种子重放出同一批点。
3. 换一份策略：不改这个插件的任何文件。
4. 写出的一批点再独立用约束核一遍，全部满足。一份故意选不可行点的策略，这些点被拦下并记成问题。
5. 没填预测器和数据也能启动；策略需要它们却没填，检查不过。
6. 人工：用一份真实的策略试一次。

## 两台机器

系统只用“Windows 连 Linux”这一个方向。Linux 不主动连回来，也不往 `data/` 里写。

| 机器 | 资源 | 跑什么 | 写什么 |
| --- | --- | --- | --- |
| Windows | CPU 多 | 操作台、值守、仪表盘；重建、FEA 求解、选点、出预测、复核 | `data/` 的全部 |
| Linux | GPU 多 | 训练的 worker | 只写自己的作业文件夹，和推过来的备份 |

### 远程执行的四个动作

都在 `hooks/remote.py` 里，直接调系统的 `ssh` 和 `scp`，连不上时退避重试。插件不自己写这一段。

| 动作 | 做什么 |
| --- | --- |
| `push` | 上传代码快照和输入的副本 |
| `start` | 在远端起一个脱离会话的 worker，立刻返回 |
| `status` | 读远端的状态文件：阶段、心跳时间、环境、结局 |
| `pull` | 把产物取回到插件的 `work/` |

远端一轮一个作业文件夹：

```
<作业根目录>/E0012/r1/
  code/         这一轮上传的快照：stemlab/ 和本插件的文件夹
  inputs/       输入的副本
  outputs/      产物，等着被取回
  status.json   阶段、心跳、环境、结局
  log.txt
```

一次训练的全过程：

1. 插件的 `start`：打快照，`push` 快照和训练数据的副本，`start` 起 worker，把任务报成运行。
2. 插件的 `poll`：`status`。没完就更新阶段；完了就 `pull`，交预测器和误差报告，说做完。
3. 核心对取回的预测器走发布的六步。哈希是在 Windows 上算的。

### worker 的规矩

- 代码每轮由 Windows 上传。这一轮记的插件哈希就是上传的这一份。Linux 上不放当真的工作副本。
- worker 读 `inputs/`，写 `outputs/` 和 `status.json`，别的都不碰。它拿不到 `handle`。
- 状态靠读状态文件，不靠查进程号。心跳停了超过设定的时间，任务记成环境问题，属于可重试。
- worker 把远端的环境写进状态文件：主机名、Python 和关键库的版本、CUDA 和驱动、GPU 型号。取回时记进这一轮的来历。
- 两台机器各一个环境，由同一份锁文件装出来。
- 预测器在 Linux 的 GPU 上训，在 Windows 的 CPU 上用。包的格式要求权重和设备无关、不存路径对象、带自检样本；第一次在 Windows 上用先过自检。

### 核心里的六条 Windows 写法

操作台在 Windows 上。这六条写错了不会报错，只会出事，所以它们都在核心里，不交给 AI 写。

| 写法 | 为什么 | 在哪 |
| --- | --- | --- |
| 查进程在不在，不用 `os.kill(pid, 0)`。用 psutil，并比进程的创建时间 | 在 Windows 上它不是探测，会用 TerminateProcess 把进程杀掉（[Python 问题跟踪](https://bugs.python.org/issue26350)）。比创建时间是防进程号被重用 | `hooks/local.py` |
| 锁单独的 `.lock` 文件，不锁链文件本身 | Windows 的文件锁是强制的，别的进程读写被锁的文件会失败（[portalocker 文档](https://portalocker.readthedocs.io/en/latest/_sources/platforms.rst.txt)），仪表盘会读不了 | 两个 `lock.py` |
| 链和清单一律按字节写：UTF-8、LF | 文本模式的默认编码在 Python 3.14 及以前跟系统区域走（[Real Python](https://realpython.com/python315-utf8-default/)），换行也会被改写。写成另一种字节，备份到 Linux 上就核对不过 | `contract/chain.py` |
| 移动和删除文件夹带退避重试；读的一方读完就关 | 打开着的文件不能改名和删除。杀毒、索引、仪表盘正好读着时会偶发失败 | `hooks/publish.py` |
| 落盘的名字用 ASCII，路径尽量短，查重时不分大小写 | 中文名过 SSH 可能乱码；Windows 路径默认有长度上限，且不分大小写 | `contract/formats/manifest.py` |
| 起脱离父进程的进程，本机和远端各写一处 | 两个系统写法不同。写错了，关掉终端求解或训练就跟着死 | `hooks/local.py`、`hooks/remote.py` |

后三条没有逐条查过文档，要在 Windows 上实测一次。

### 跨机测试 `tests/cross/`

1. 同一个文件夹在两台机器上 `hash_tree` 相同。
2. 同一个预测器两边的预测在容差内相同。
3. SSH 中途断开：worker 不受影响，`status` 能接上。
4. 备份推过去之后，在 Linux 上跑核对能过。

锁、断电、并发这三组测试，在 Windows 上过了才算数。

## 守边界

每条规矩都由一样工具或一个测试守着，不靠自觉。一条命令跑全部：`python -m stemlab.desk.core.check`，提交之前自动跑一次。

| 规矩 | 靠什么守 | 在哪 |
| --- | --- | --- |
| 块之间谁能用谁 | import-linter，八条规则 | `.importlinter` |
| 固定的文件不被顺手改 | 清单里记着每个固定文件的哈希，文件和清单对不上就不过。清单覆盖契约、核心、插件的冻结文件、`tests/`、`.importlinter` | `FROZEN`、`tests/guard/` |
| 插件不直接碰 `data/` | 扫插件的源码：不出现 `data/` 的路径和两条链的文件名 | `tests/guard/` |
| 只许一处叫的函数 | 扫源码：`register_output` 只在 `hooks/publish.py` 里被叫；`os.kill` 不出现 | `tests/guard/` |
| 格式和状态表不漂 | 契约测试 | `tests/contract/` |
| 断电不留半截 | 在启动和发布的每一步之后掐断，再对账 | `tests/crash/` |
| 插件再糟也扛得住 | 示范插件和坏插件 | `tests/plugins/` |
| 界面和仪表盘只读 | 开着它们前后，比 `data/` 下每个文件的哈希 | `tests/guard/` |
| 两台机器对得上 | 跨机测试 | `tests/cross/` |
| 物理上对不对 | 你定的算例和容差。这一项不交给 AI | `tests/science/` |
| AI 的范围 | 写给 AI 的规矩；越界由上面几项查出来 | `CLAUDE.md` |

### 坏插件

`tests/plugins/` 里除了示范插件，再放一个故意越界的。它每犯一样，核心都要扛得住。

| 坏插件做的事 | 应该发生什么 |
| --- | --- |
| 检查里往记录写 | 被拒。记录里不多一条 |
| 交一样产物表里没有的产物，或者种类不符 | 发布的第 1 步拒绝，记成问题 |
| 交一批条件没写全的点 | 发布的第 2 步拒绝，说出缺哪一项 |
| 动作里抛错 | 记成问题，不往外抛，别的实验照常 |
| 启动到一半进程退出 | 实验停在启动中；值守下一遍记成启动失败 |
| 源码里直接打开 `data/` 下的文件，或 import 挂点的子模块 | 源码扫描和依赖规则报出是哪个文件哪一行 |
| 把自由的部分整个换一份写法，接口不变 | 契约测试、别的块的测试、已有实验的核对，全部照过 |

源码扫描和坏插件测试是为了发现写得粗糙的代码，不是防恶意代码。

### 写给 AI 的规矩

```
# CLAUDE.md

## 能写的
- plugins/*/ 里没标冻结的文件，和 plugins/*/tests/
- stemlab/desk/ui/、stemlab/board/

## 只能读，不能改
- stemlab/contract/、registry/、experiments/、hooks/、desk/core/、desk/__main__.py
- plugins/*/ 里标了冻结的文件
- tests/、FROZEN、.importlinter、.gitattributes、machines.json

## 每次改完
- 跑 python -m stemlab.desk.core.check。不过就不算做完
- 不为了让检查通过去改测试、清单或规则。过不了就停下来说明原因
```

`FROZEN` 清单的改法只有一种：单独一次提交，只改清单和它锁着的文件，提交说明里写为什么改。AI 不改清单。源码的换行用 `.gitattributes` 固定，这样两台机器上的哈希才一致。

## 搭建顺序

先把测试写出来并放进固定的部分，再动手实现。每块“怎样算做对”的清单就是这些测试的目录。

| 阶段 | 做什么 | 谁写 | 做完的标志 |
| --- | --- | --- | --- |
| 0 走通一条线 | 每块只写最小的一条路径：登记一个值，新建，启动，示范插件交一样产物，发布，往上追。几百行，写完就扔 | 随便写 | 一条命令从登记跑到追溯。块之间的接口哪里别扭，这时就知道 |
| 1 契约 | 九个机制文件，和 `formats/` 里的 `manifest`、`points`；`tests/contract/` | 你定，逐行看 | 契约测试全过 |
| 2 立规矩 | 带真实 import 的骨架；八条规则；`FROZEN`；源码扫描；检查的入口；`CLAUDE.md`；`.gitattributes` | 你定 | 骨架上检查全过；故意越界时各自报错 |
| 3 核心 | 按这个顺序：登记；实验记录；挂点的 `call`、`publish`、`local`；操作台核心的 `start`；断电测试；值守；包的格式和 `entry`；`remote` 和跨机测试；备份 | 有设计地写，不放开 | 示范插件走通；坏插件七样都扛住；每一步掐断后对得上账。这些都在 Windows 上过 |
| 4 FEA，再重建 | 各自先定格式（`data`、`bone_model`），写冻结文件，用假的计算走通，再写自由的 | 冻结的你看过；自由的放开 | 自动的验收全过；科学的验收你签过 |
| 5 代理和优化 | 先写 7 个冻结文件和它们的测试，用最简单的模型和示例策略走通，包括在 Linux 上训一次；再放开 | 冻结的你看过；自由的放开 | 同上 |
| 6 界面 | `desk/ui/`、仪表盘、各类型的图表 | AI | 每次改完检查全过 |

阶段 0 的代码不进仓库。它的用处是让阶段 1 要固定的接口先被真实地用一次。FEA 排在重建前面，是因为内核怎么调要先在这里定下来，重建的检查门和候选池都要用。阶段 6 之前只用命令行的最小版本。

## 1.0 不做的，和要你给的

### 不做的

- 暂停和继续。停止再启动就够。
- FEA 在 Linux 上算。`remote` 写好之后，要加随时能加。
- 结果缓存。输入指纹先记下，“这个作业算过没有”以后再做。
- 多个写入者，或把 `data/` 放在网络盘上。
- 自动把头颈部内壁重建到可信；按 CT 值逐点赋材料；批量重建。
- 比较模型好坏、比较策略好坏。这些在系统外做，做好的登记进来。
- 复现任何已有代码的结果。
