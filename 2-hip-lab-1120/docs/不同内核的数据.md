# 不同内核算出来的数不放在一起用

一个点的哈希由骨、设计、条件算出，里面没有内核。以后换了柄的参数化方式、放置方法或者求解的做法，做成一个新的内核包，
它算出来的数和旧内核的列名一样、单位一样，系统原来分不出来，会被合进同一次训练或同一次选点。现在这一条由系统拦住。

## 第 2 版（2026-11-16，改格式的 D2）

下面几节写的是第 1 版，只记内核和推导量定义，照样认。第 2 版多记几样：

| 段 | 记什么 |
| --- | --- |
| `stem`、`fem` | 柄空间包、有限元包，拆内核以后用。`stem` 写 `"none"` 是无植入物 |
| `settings` | 放置、有限元、推导量三份设定里，所有点都一样的那部分的哈希。只管怎么跑的项不算，比如 FEA 导出设定里的求解槽、超时 |
| `bones` | 每根骨用的是哪一版骨模型，按骨标识记 |
| `predictions` | 用到的预测 |

**比法**：
- **合在一起用**（几份数据一起训练、一起选点）：每两份都比。
  - 算的包要一样；推导量照旧，只在都记了的那几份之间比；
  - 设定要一样；同一根骨要是同一版骨模型，不同的骨不冲突；用到的预测要一样；
  - 知道的和不知道的不放在一起。第 1 版缺的几样就是“不知道”：两份都是第 1 版的照旧能放在一起，第 1 版的和第 2 版的不行。
- **一起用但不合并**（预测器和候选池、数据和候选池、一份预测和拿来复核的数据）：只比两边都记了的那几样。候选池本来就不用有限元的设定。
- **合起来记的那一份**：预测器的 made_by 由契约的 `common_maker` 合，插件不自己拼。

写法和比法都在 `stemlab/contract/formats/manifest.py`。

## 记：清单里的 made_by

数据、候选池、预测器、一份预测的清单里记着里面的数是哪个内核（和哪份推导量定义）算的：

    "made_by": {"kernel": 内核是哪一个, "derive": 推导量定义是哪一个，没有推导量就是 null}

- 内核包的清单里写了 `model`（带 `name`），记的就是 `model` 原样。现在的真内核是
  `{"name": "M1-3406-v1", "code_hash": "6d7af243d0", "solver": "Abaqus/Standard 2025"}`。
  所以同一套内核代码重新打一次包（比如换了自检样本），只要 `model` 没变，算出来的数还算同一个内核的。
- 内核包没写 `model` 的，记的是这个包的哈希。
- 推导量定义记它的包的哈希。

谁写：

| 东西 | 谁写 made_by |
| --- | --- |
| 数据 | fea.run 导出数据时，照填的内核包和推导量定义 |
| 候选池 | opt.pool，照填的内核包（推导量定义是 null） |
| 预测器 | 训练时，照它的训练数据 |
| 一份预测 | 出预测时，照预测器 |
| 旧库 v0.14 转来的数据 | 转换时，照内核包的 `model`（推导量不转，所以是 null） |

## 拦：启动前的检查

| 实验 | 规矩 |
| --- | --- |
| 训练（surrogate.train） | 几份数据一起训练，都得记着，而且是同一个内核；推导量定义也得是同一份（记了推导量定义的那几份之间比，旧库这样没有推导量的不比）。只有一份数据，不用比 |
| 选点（opt.select） | 几份数据同上；候选池和预测器记了的，要和数据、和彼此是同一个内核（两边都有推导量的，推导量定义也得相同） |
| 复核（surrogate.check） | 预测和数据都记了、又不是同一个内核（或者两边的推导量不是同一份推导量定义算的），不比 |

不过就启动不了，原因里写着各是哪个内核算的。

没记的（外面拿来、清单里没写 made_by 的数据）单独用可以；要和别的放在一起，先在它的清单里写上是哪个内核算的再登记。

## 旧库 v0.14

转换时记成 M1-3406-v1（代码哈希 6d7af243d0），和用 `external/kernel_m1_3406` 打的包跑的参照包那条（拆内核以前叫 fea.run，
2026-11-16 起叫 fea.reference）的数据记的一样，所以两份能放在一起。
转换只收这个代码哈希的行：2026-11-15 核过，v0.14 里收下的 1157 行都是。

## 拆内核以后（2026-11-16）

`fea.run` 用柄空间包加有限元包算，数据的 made_by 由契约的 `made_by_split` 写：`kernel` 是 null，
`stem`、`fem` 记两个包的哈希（无植入物 `stem` 写 `"none"`），三份设定里所有点都一样的那部分各记哈希。
它和参照包算的数 `kernel` 不同，不放在一起用；拆出的两个包和参照包算得一不一样，暂时不判（你 11-16 定的），两边的数可以并排看。

## 没做的

- 故意把两个内核的数放在一起（比如训练一个把“哪个内核”当成特征的模型）：现在不行。要的话，得另加一个明说的开关。
- 一批点不记 made_by：它只是设计和条件，用哪个内核算是 fea.run 的事。

- `plugins/opt/plugin.py`：候选池记 made_by；选点前核对
- `plugins/surrogate/plugin.py`、`plugins/surrogate/predictor.py`：训练前核对；预测器、一份预测记 made_by；复核前核对
