# 场的代理

蓝图的代理模块里，`models/` 那一格写的是“标量的和场的预测器”。原来只有标量的那一半：一份预测的格式、打包、
误差报告都只认标量。这份文件说场的那一半现在放在哪、怎么用、限度在哪。

## 现在有什么

场和标量走同一套规矩，都在固定的部分里，换模型不用动它们：

| 哪一步 | 场是怎么走的 | 在哪个文件 |
| --- | --- | --- |
| 一份预测的格式 | 列里可以有 role 是 `field` 的列；行里用 `fields` 写这个点的场存在 `fields/` 下的哪个文件 | `stemlab/contract/formats/data.py` |
| 训练 | 训练设定里写 `fields`。交给训练代码的只有训练那一部分的场；留出和往外推的点，场的真值留在操作台 | `plugins/surrogate/plugin.py` |
| 打包 | 清单的 `columns` 里多出场的列，另加 `shapes`。入口核过形状、有限、下界 ≤ 值 ≤ 上界，才把场写出来 | `plugins/surrogate/predictor.py` |
| 误差报告 | 逐个格子比，所有留出点的格子合在一起算，用的还是 rmse、mae、bias、r2、max_abs、coverage 这几个名字。合格线的 `target` 可以写场的名字 | `plugins/surrogate/report.py` |
| 出预测 | 预测出来的场抄进这份预测的 `fields/` 下 | `plugins/surrogate/plugin.py` |
| 复核 | 预测的场和 FEA 的场按点对齐，对得上的点逐个有均方根差；形状对不上的数出来，不硬比 | `plugins/surrogate/report.py` |

预测出来的场是一个 `.npy` 文件：值、下界、上界三个同样形状的数组摞在一起，第一维是 3。

自由的部分带了一个最简单的场模型 `pod`（`plugins/surrogate/models/pod.py`）：每个格子减去均值，做奇异值分解留前几个模态，
各个设计在这几个模态上的系数用和 `ridge` 同一套二次岭回归去学。它是用来把这条路走通的，不是定下来的做法。

训练设定的写法：

    {"targets": ["rot_first_deg"], "fields": ["某个场的名字"], "seed": 11, "model": {"name": "pod"}}

`targets` 可以是空的（只预测场）。选的模型不会预测场（比如 `ridge`），启动前就被拒。

## 能学的场是哪一种

每一行形状都一样的数组，比如重采样到同一张网格上的场。训练的各行里形状不一样，这一轮照实做不下去，原因里写着两个形状。

**现在内核给的界面场不是这一种。** M1-3406-v1 给的 `interface` 是点云：每个节点对的位置、法向、面积、过盈、四个分析步的相对位移。
各个设计的节点数不一样，所以它现在学不了。要学它，得先把它换成各个设计共同的写法。旧系统的 `ml3406` 里试过三种
（网格视图、图、体素）。这一步有三件事要定，都是科学上的选择，没有替你定：

1. **预测哪个场、在什么坐标上。** 比如把第二循环的切向微动重采样到柄自己的坐标网格（沿柄轴 × 绕柄一周）上。
2. **这一步放在哪。** 放在内核的后处理里（内核多给一个形状固定的场），还是放在推导量定义里。两种都是登记一个新的包，不动系统。
3. **要不要把界面的几何当输入。** 图那一类模型要每个点的界面几何（建模之后、求解之前就有）。现在出预测的输入只有“预测器”和“一批点”，
   没有地方给几何；要这样做，得给内核的清单加一类“建模时就有的场”，出预测时先叫内核建一次模。这是对固定部分的又一次改动。

第 1、2 件定了，现在这套就能直接用；第 3 件是以后要不要再扩的事。

## 核对过什么

自动的测试在 `tests/contract/test_data.py`（预测的格式）、`tests/plugins/test_surrogate.py` 和 `surrogate_cases.py`（三个情形：
一个场从训练、出预测到复核走通；只预测场；学不了的场被拒），跟着检查一起跑。用的是假内核的场（界面上五个节点的滑移），
所以验的是“这条路通不通、规矩守没守住”，不是哪种场模型好。

跨机测试里另加了一条（2026-11-15 跑过，过了）：带场的训练派到 Linux 那台上做，打出来的包拿回 Windows 上出预测，
两边出的场在容差内相同。

## 这次动了固定的部分

为了给场一个位置，动了契约和代理插件的冻结文件，`FROZEN` 清单跟着重新生成：

- `stemlab/contract/formats/data.py`：一份预测可以带场。原来“一份预测的文件夹里只该有 rows.jsonl”这一条没有了，
  换成和数据一样的规矩：别的文件都在 `fields/` 下，而且每个都有行指着。原来的预测（没有场）照样合格。
  格式的版本号没有升：改动只是放宽，旧的预测在新代码下照样合格；反过来，带场的预测拿旧代码读会被当成坏数据。
  改的时候账本里一样登记都没有，没有受影响的旧数据。
- `stemlab/contract/formats/package.py`：只改了说明文字。
- `plugins/surrogate/plugin.py`、`predictor.py`、`report.py`：加上场的那一半。只预测标量时，行为和原来一样；
  原来打的包照样能用（验收里“换模型之前打的包照样出同样的预测”那一条照过）。
- `tests/` 下：`contract/test_data.py`（“带了场文件”那一条坏样本，改成“有没人指着的场文件”，另加场的好坏样本）、
  `plugins/surrogate_cases.py`、`plugins/test_surrogate.py`、`real.py`（造带场的数据）、
  `cross/test_surrogate_cross.py`（场也在 Linux 上训、在 Windows 上用，两边出的场在容差内相同）。

这些文件改了，`FROZEN` 清单就对不上，检查里“固定的文件和 FROZEN 清单对得上”那一项不过。清单没有替你重新生成：
固定的部分由你看过才算数，清单只在你同意之后、单独一次提交里改（`python -m stemlab.desk.core.code_state freeze`）。
不同意的话，把上面这些文件退回去就是原样，场的这一半就又没有位置了（自由部分里的 `pod` 模型和图表改动可以留着，用不上而已）。
