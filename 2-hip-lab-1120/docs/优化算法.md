# 优化算法

优化分两步，都是实验：先“出候选池”，再“一次选点”。选出来的是一批点，直接填进 FEA 实验。
算完的数据回来之后再选下一批，一轮一轮往下走。

这份文件说两件事：候选池有哪几种取法，选点有哪几种算法；各自什么时候用、要什么、限度在哪。

## 候选池的取法

写在设计范围里的 `method`，不写就是 `lhs`。代码在 `plugins/opt/pool.py`。
只取几个值的项（比如入口偏移写 `rule`）哪种取法都是随机挑一个。同一份范围加同一个种子，取出来的是同一批设计。

| `method` | 怎么取 | 什么时候用 |
| --- | --- | --- |
| `lhs` | 拉丁超立方：每一项把范围切成 count 段，各段取一个，打乱了配对 | 默认。每一项上都铺得匀 |
| `sobol` | Sobol 序列（打乱过的） | 整个范围里铺得匀；旧系统的候选池就是这样取的 |
| `random` | 每一项各自随机取 | 做对照用 |
| `around` | 围着给的几个设计取。另写 `centers`（一组设计）和 `spread`（默认 0.1）：每个数值项在“中心 ± spread × 这一项的范围宽度”里取，出了范围的截回来。中心自己排在最前面，也进候选池 | 已经有了好设计，想在它附近细找 |

每个设计可不可行由内核的模板化说。旧系统的统计：v1 盒子里随机取的设计大约 13% 放得进 3406 这根骨。

## 选点的算法

选点的算法是登记进来的“策略”包，一种算法一个包。做法在 `external/strategies/`，每个文件开头写着它是怎么选的。

| 策略 | 打包时的名字 | 要填什么 | 怎么选 | 什么时候用 |
| --- | --- | --- | --- | --- |
| 均匀铺点 | `spacefill` | 都不用。数据可填可不填 | 把设计各项缩放到 0 到 1，逐个挑离“已选的点和已经算过的点”最远的 | 第一批点；把还空着的地方补上 |
| 贝叶斯优化 | `bayes` | 数据 | 拿已有的 FE 结果在策略内部拟合高斯过程，挑期望改进最大的 | 已经有了一批 FE 结果之后 |
| 照预测值选 | `predicted-best` | 预测器 | 照登记的预测器的预测值，从好到坏 | 有了可信的预测器，想收口 |
| 照预测区间有利的一端选 | `predicted-optimistic` | 预测器 | 照预测区间里有利的那一端，把“可能很好但没把握”的也放进来 | 有了预测器，还想兼顾探索 |

四种共同的规矩：

- 只在“能选的候选”里选：候选池里可行、满足目标和约束里“不做 FE 就判得了的约束”。选出来的点系统还会再核一遍，不满足的拦下。
- 给了数据，就不再选已经算过的设计（同一根骨、条件和这次选点的条件默认逐项相同）。
- 同样的输入加同样的种子，选出同样的点，所以可以重放。
- 每个点的理由里写着分数和为什么选它；用了模型的，写着是哪个模型。

### 均匀铺点

一个算过的点都没有时，第一个点照种子取，换一个种子就是另一批。分数是这个点离已有的点的距离。

### 贝叶斯优化

- **用哪些数据。** 给的数据里同一根骨、条件和这次的条件默认逐项相同、目标的各列都有数的行。
  这样的行不够 max(6, 设计的坐标数 + 2) 行就不选，结局是“策略出错”，问题里写着差多少。
- **模型。** 每个目标一个高斯过程（Matern 5/2，每个设计项各一个长度）。全是正数的目标（微动、转动）取了对数再拟合。
- **一个目标。** 期望改进：这个候选比现在算过的最好的还好多少，按预测的分布取平均。
- **几个目标。** ParEGO 的做法：每选一个点换一组随机权重，把几个目标合成一个数，对它算期望改进。
  选出的点沿着几个目标之间的取舍铺开。目标里写的 `weight` 乘在随机权重上：权重大的目标更常被照顾到。
- **一批点。** 逐个选。选中一个，先当它算出来的正好是预测的均值，再选下一个，这样同一批里的点不会挤在同一处。
- 理由里写着每个目标的预测值和 95% 的区间，换回了原来的单位。

要知道的几点：

- 数据里已经有很好的点时，期望改进会转去试模型没把握的地方。这是这种算法本来的行为，不是出错。
- 放不进去、不收敛、不稳定的点没有被当成信息用：模型只看算出了数的行。
- 数据超过 1500 行时只用其中 1500 行：各目标最好的四分之一，加上照种子随机取的。
- 入口偏移有的写 `rule`、有的写数时，它被当成“只取几个值的项”处理，每个值一列。

### 用预测器的两种

- 不在预测器适用范围里的候选没有预测，不选。
- 几个目标时先分层：没有被别的候选在每个目标上都压过的是第一层（预测的帕累托前沿），一层一层往下取；
  同一层里照各目标缩放之后的加权和，从好到坏。
- 和已选的点离得太近的先跳过（各设计项缩放之后的距离小于 0.05），不够数再补回来。

## 实测

自动的测试在 `tests_free/strategies/` 和 `plugins/opt/tests/`，跟着检查一起跑：算法本身（人造的小问题，答案手上有数），
和打成包之后经真的优化插件走一遍（点交得出来、理由写全、可以重放）。

另外拿旧数据库 v0.14 的真实 FE 结果做了一次回溯（2026-11-14，不在自动的测试里）。
基线条件下算过的 668 个设计，随机藏起四成（267 个）当候选池，剩下 401 个当已有的数据，让策略从候选里选 16 个；换三个种子各做一次。

| 目标 | 结果 |
| --- | --- |
| 微动 `f1_p95_um`，往小里优化 | 三次都选中了候选里真正最好的那一个，前四名里选中了三到四个。随手抓 16 个，抓到最好那一个的机会是 6% 左右。用时 3 秒 |
| 微动和去骨量 `bone_total_mm3` 两个目标 | 多压住的面积（超体积，对数刻度）是随手抓 16 个的 9 到 13 倍，达到“把 267 个候选全算了”的 65% 到 73%。用时 6 秒 |
| 均匀铺点 | 铺出来的 16 个点两两最近的距离是 1.45，随手抓的平均是 0.25 |

这是在已经算过的设计里回溯，说明模型和选法在这类数据上管用；它不等于在全新的候选池上也有同样的效果。

## 怎么用

打包（四种各打一个）：

    python external/strategies/build.py spacefill <包放到哪个文件夹>
    python external/strategies/build.py bayes <文件夹>
    python external/strategies/build.py predicted-best <文件夹>
    python external/strategies/build.py predicted-optimistic <文件夹>

登记：

    python -m stemlab.desk register strategy <名字> --path <包的文件夹> --note "..."

之后在“一次选点”的实验里，策略这一项填它的编号。

## 没做的

- 旧系统用 botorch 做的多目标贝叶斯优化没有搬过来。这里的贝叶斯优化是用 numpy 和 scipy 另写的，做法不同（ParEGO），依赖少。
- 没有“算不算得出来”的概率模型：候选会不会不收敛、不稳定，策略不预测。
- 不同条件下算出来的数据不能合起来用。
- 策略没有可以在页面上调的设置。要改做法，得改代码重新打包，登记成新的一版。
- 比较哪种策略更好，蓝图定的是在系统外做。
