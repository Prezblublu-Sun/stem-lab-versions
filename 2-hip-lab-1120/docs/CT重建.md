# CT 重建

重建插件有两条路。CAD 骨源的两个实体原样用。CT 骨源照这份文件说的做法，从一份 CT 和一份股骨外形，
做出皮质和松质两个封闭的实体，再照常找标志点、过检查门、定稿成骨模型。

做法是 2026-11 的第二版 CT 流程（`G:\projects\application\femur_ct_rebuild_2026-11-04`，
《单根股骨建模流程详解》的第 1 到 17 步），参数的默认值也是那一版的。代码在 `plugins/recon/ct.py`（第 1 到 15 步）
和 `plugins/recon/solids.py`（第 16、17 步）。

## 要什么

一份登记的骨源（一个文件夹），里面有：

- **CT**：nrrd、nii（或 nii.gz）、mha。一组 DICOM 这里不直接读，要先转成一个 nrrd（比如用 3D Slicer 导出）。
  有好几段 CT 时可以都放进来：用装得下这根股骨的最小的那一份。
- **这根股骨的外形**：一个 STL 或 PLY 表面，人工描的，或者别的软件分割出来的。要和 CT 是同一次扫描。
  外形和 CT 的坐标约定不一样（两种病人坐标系，或者 CT 上下颠倒存放）时会自动对上：三种约定里取和 CT 重合最多的，
  重合不到 0.8 就不做。

**外形必须有。** 只有 CT 时，靠阈值和形态学把股骨和骨盆、胫骨分开，当时实测 12 例全部失败，所以这里不做自动分骨。
蓝图的模块表里 `rebuild.py` 写着“分骨”，这一步现在是靠你给的外形完成的，不是自动的。

## 怎么做的

| 步 | 做什么 | 默认值 |
| --- | --- | --- |
| 1 | 外形只留最外层的一个表面（有的模型里还带着内表面和碎片） | |
| 2 | 选 CT、定坐标约定 | 重合不低于 0.8 |
| 3 | 在外形周围截取 CT，重采样成各向同性的体素 | 0.7 mm，每边外扩 6 mm |
| 4 | 外形变成实心掩膜 | |
| 5 | 皮质候选：外形以内、CT 值不低于阈值 | 500 HU |
| 6 | 两端限深：离外表面比上限更深的不算皮质 | 髁部 3 mm，头颈部 5 mm，骨干不限 |
| 7 | 皮质闭运算 | 半径 1 个体素 |
| 8–11 | 内部 = 股骨 − 皮质；开运算；取最大块；闭运算，填洞 | |
| 12 | 比上限深的并回内部 | |
| 13 | 最小壁厚：内部只能落在“股骨向内收 N 个体素”的范围里 | 2 个体素，即 1.4 mm |
| 14 | 再取最大块，就是内部（松质和髓腔）；皮质 = 股骨 − 内部 | |
| 15 | 两个掩膜各自高斯平滑、取等值面、网格平滑、只留最大块、减面 | 外 0.7 mm、内 1.2 mm；20 次；12 万个三角形 |
| 16 | MeshLab 修复，再等边长重划 | 外表面 2.5 mm，内壁是它的 0.8 倍，迭代 8 次 |
| 17 | 试划一次四面体（皮质一个区、松质一个区，界面共用节点），量单元质量 | 网格不留，只留量出来的数 |

交出来的两个实体是两个 STL：皮质 = 外表面加上法向朝里的内壁，松质 = 内壁。内壁在两个文件里是同一组顶点。
实体和标志点都在 CT 自己的坐标系里（外形的坐标约定和 CT 不一样时，以 CT 的为准，重建记录里写着换了哪几个方向）。

当时的第 18 步（升二阶、导出 Abaqus 的 inp）不在这里：FEA 用的网格由内核照它自己的需要去划。

## 重建设定怎么写

和 CAD 骨源的重建设定是同一种东西，`side`、`frame`、`materials`、`gate` 照旧，另外：

    "source": {"outer": "Femur_R.ply", "ct": "ct.nrrd"},
    "ct": {"cortical_hu": 500, "edge_mm": 2.5}

`source.ct` 可以不写（骨源里的体数据文件都算候选），也可以写一组。`ct` 里各项都可以不写，不写就是默认值：

| 项 | 意思 | 默认 |
| --- | --- | --- |
| `cortical_hu` | 皮质的 CT 值下限 | 500 |
| `voxel_mm` | 重采样的体素边长 | 0.7 |
| `margin_mm` | 截取时每边外扩 | 6 |
| `depth_cap` | 两端限深：`[[位置, 上限毫米], ...]`，位置 0 是远端、1 是近端。写 `null` 就不限深 | `[[0,3],[0.1,3],[0.22,60],[0.72,60],[0.85,5],[1,5]]` |
| `min_wall_voxels` | 最小壁厚，几个体素 | 2 |
| `proximal` | 近端在哪一头：`auto`（照外形判断）、`high_z`、`low_z` | `auto` |
| `outer_sigma_mm`、`inner_sigma_mm` | 两个表面的高斯平滑 | 0.7、1.2 |
| `relax`、`triangles` | 网格平滑的次数；细表面减到多少个三角形 | 20、120000 |
| `edge_mm` | 外表面重划的目标边长 | 2.5 |
| `inner_factor` | 内壁的边长是外表面的几倍 | 0.8 |
| `remesh_iterations` | 重划迭代几次 | 8 |
| `tet_check` | 做不做第 17 步 | `true` |

当时 159 根里有 4 根要把边长换成 2.3 或 2.7 mm 四面体才合格：`edge_mm` 是最常要动的一项。

另一项要知道的是 `triangles`（第 15 步的减面）。很直的圆柱段会被减成上百毫米长的细长三角形，MeshLab 重划时在那一段翻面，
四面体就划不成（gmsh 报面片重叠）。真实的股骨上没见到（z061 用默认的 12 万是好的）；测试里那根造出来的假股骨骨干是完美的圆柱，
就撞上了。把 `triangles` 写得比细表面实际的三角形数多（比如 5000000），就是不减面，重划反而更快。
四面体划不成不算重建出错：原因记在 `tet_check_problem` 里，待检查清单会标出来，检查门里拿四面体质量来比的线自然不过。

设置页面的设计稿（`docs/实验设置页面.html`）里，重建两页把“骨源是哪一种”选成 CT，就是这些项。

## 量出来的数，和检查门常用的线

CT 这条路另外量的数（都写进骨模型的 `measures`，检查门可以拿来比）：

| 量 | 意思 |
| --- | --- |
| `surfaces_open_edges` | 重划之后两个表面的开放边条数。0 就是都封闭 |
| `remesh_deviation_p95_mm` | 重划之后离原来的表面多远（95% 分位，两个表面里大的那个） |
| `wall_min_mm`、`wall_p05_mm`、`wall_median_mm` | 皮质的厚度：内壁上各点到外表面的距离 |
| `tet_gamma_min`、`tet_inverted`、`tet_count` | 试划的四面体：最差的单元质量、翻转的个数、单元数 |
| `outer_vs_reference_mean_mm`、`outer_vs_reference_p95_mm` | 重建的外表面和你给的外形差多少 |
| `cortical_mesh_volume_error`、`cancellous_mesh_volume_error` | 表面围出的体积和体素数出来的体积差多少（比例） |
| `surface_on_bone_share` | 外形两侧各一个体素的那一层里，够得上骨的 CT 值（200 HU）的比例：外形是不是压在骨面上 |
| `cortex_added_by_rules_share` | 最终的皮质里有多少不是阈值直接得到的，是限深和最小壁厚补出来的 |
| `proximal_end`、`long_axis_tilt_deg`、`ct_flip`、`ct_file` | 近端判在哪一头；骨的长轴和 z 方向的夹角；坐标约定；用的哪份 CT |
| `isthmus_canal_diameter_mm`、`isthmus_cortex_index` 等 | 骨干最细处的髓腔直径、外径、皮质占比 |

当时定的合格标准是四条，设置页面选 CT 时默认带上：

| 检查 | 线 |
| --- | --- |
| 两个表面都封闭 | `surfaces_open_edges` 不大于 0 |
| 重划没有走样 | `remesh_deviation_p95_mm` 不大于 0.3 |
| 四面体质量 | `tet_gamma_min` 不小于 0.1 |
| 没有翻转的四面体 | `tet_inverted` 不大于 0 |

线由你定，写在重建设定的 `gate` 里。

## 哪里要人看

待检查清单（`recon.draft` 的第二样产物）里，CT 的骨每一根都有这一条：

> 股骨头、颈和髁部的内壁不是量出来的：那里的皮质太薄，CT 上够不到阈值，是照“两端限深”和“最小壁厚”补的。

这和蓝图“1.0 不做的”里写的一致：不保证头颈部的内壁可信。做近端的分析之前，请在系统外对着 CT 看截面：
3D Slicer 里同时打开 CT 和候选骨模型 `solids/` 下的两个 STL（它们就在 CT 的坐标系里）。
要改就把改好的实体登记成“人工修改”，定稿时填上，改了什么会记进骨模型的重建记录。

改内壁时只用交一个文件：一个封闭的内壁表面（STL），在人工修改里写成换 `cancellous`。
定稿时皮质实体会照新的内壁重写（外表面不变），两个实体在界面上才对得上；这一步也记进重建记录。
同样，只换 `cortical`：它带着内壁（两块），松质就照这份内壁重写；它只有一个外表面，就配上原来的内壁。
两个都换了的，原样用。定稿时量 `interface_gap_max_mm`（皮质实体带的内壁和松质实体的表面最远差多少），
检查门可以拿它来比；改过的两个表面相交、四面体划不成时，原因记在 `tet_check_problem` 里，拿四面体质量来比的线自然不过。
交的不是 STL（比如 STEP）或者块数不对，就不重写，重建记录里写明；壁厚、界面间隙、四面体这几项量不了。

定稿时从候选照抄过来的数只有两种（2026-11-15 起）：CT 那一步的（体素、掩膜、细表面，清单在 `ct.MEASURES`），
和两个实体都没换过时重划那一步的（`solids.REMESH_MEASURES`）。别的数说的是候选的几何，定稿这次没量成就是没有数，
重建记录里列出来，检查门里拿它们比的线不过，不拿候选的数充数。

另外这几种情况清单里会标出来：外形没有压在骨面上；骨内有金属；重建的外表面离外形太远；近端的两种判法对不上；
骨的长轴和 CT 的 z 方向差得多（限深是沿 z 一层一层算的）。

## 环境

CT 这条路要三个库：SimpleITK、VTK、MeshLab（pymeshlab）。它们在 `pyproject.toml` 的 `recon` 这一组里，
版本和当时用的一样；只在操作台那台装，worker 不装。

代码里不写 `import vtk`，只装用得到的八个 VTK 模块（`ct.toolkit()`）：整个包有一百多个模块，连渲染的都在里面，这里用不到。

**这台 Windows 上的 360。** 这三个库装上之后第一次被加载时，360 的实时防护（`360rp.exe`）会把加载过的库文件打开并占住，
占着的时候 Python 加载不了它们，报“另一个程序正在使用此文件”；gmsh 的库文件（`.venv\Lib\gmsh-4.15.dll`）也会被连带占住。
是哪个进程占的，是用 Windows 自带的重启管理器查实的。2026-11-14 下午它一占就是几十分钟、不见放开，直到机器重启；
重启之后（11-15）第一次加载时又占了几分钟，放开之后再加载就不占了。所以装完或重启后头一回跑，可能要等几分钟再跑一遍。
这不是代码的问题。360 的设置没有人动过：要不要把 `.venv` 加进它的信任区，由你定。
要这三个库的测试在库加载不了时会跳过并写明原因——看到跳过，不等于那部分验过了。

## 没做的

- 自动分骨（见上）。
- 头颈部和髁部的内壁没有做到可信；全程没有内壁的真值可比（当时只有 patient1 有手工内壁）。
- 按 CT 值逐点赋材料。两个实体各用一种材料，写在重建设定的 `materials` 里。
- 批量重建。一个实验重建一根骨。
- 直接读 DICOM。
- 给人看的截面图。仪表盘上现在只有数和清单，看截面要到 3D Slicer 里看。
- **接 FEA。** 现在登记得了的内核（M1-3406-v1）只认 sawbone3406 这一根 CAD 骨，它的建模用的是 CAD 实体。
  CT 重建出来的骨模型（两个三角网实体）要进 FEA，得先有一个认它的内核包。
