## 一 机器清单（查到的）

写在 `machines.json`。

| 机器 | 角色 | 查到的 | 定的 |
| --- | --- | --- | --- |
| DESKTOP-LQNAMNB（Windows） | 操作台 | Ryzen 7 9700X，8 核 16 线程，内存 61.6 GB；Abaqus 2025，启动器 `D:\SIMULIA\Commands\abq2025.bat` | 求解槽 3 个：旧系统就是 3 个作业并行、每个 5 核 |
| linuxworkstation（Linux） | worker | i5-12400F，内存 31 GB，RTX 5060 Ti 16 GB；Ubuntu 24.04，系统的 Python 3.12.3 | 环境 `/home/linux-user/stemlab-env/venv`（照 `uv.lock` 装的），作业根 `/home/linux-user/stemlab-jobs`，备份根 `/home/linux-user/stemlab-backup`（ext4，剩 145 GB） |

- `/mnt/nvme` 是 Windows 双系统盘的 NTFS 分区，不用它；`/dev/nvme0n1` 不碰。
- Linux 上的环境是 2026-11-13 你说“装”之后照 `uv.lock` 装的，在 `/home/linux-user/stemlab-env/` 下：`venv/` 是环境，
  `tools/` 只放 uv 0.13.8（和 Windows 同一版），`lock/` 是送过去的锁和两个脚本。Python 3.12.3，16 个包，
  版本和 Windows 这边逐个相同（Windows 多的只是 pytest、import-linter 这些开发用的）。机器清单里 worker 的 `python` 指着它。
  没用 sudo；包从 PyPI 下，下载缓存在那台机器原有的 `~/.cache/uv`；除此之外只动了 `stemlab-env` 这一个文件夹。
  重装或核对用 `python worker_env/sync.py`（加 `--check` 只看不装）。
- gmsh 在 Linux 上另要一个系统库 `libGLU.so.1`，它不在锁里，锁管不到：Ubuntu 上是 `libglu1-mesa` 包，要 sudo 装。
  2026-11-14 你自己装上了（`sudo apt install libglu1-mesa`，9.0.2-1.1build1）。装之前 gmsh 装得上但导入不了。
  重装系统或换一台 worker 时要记得装这个包；缺了它 `sync.py` 会报“gmsh 装上了但导入不了”。
- 装完实测：Linux 的环境里 gmsh 能用 OCC 建实体、划三维网格，体积和 Windows 上算的一样。
  但同一个实体、同一版 gmsh，两台机器划出来的网格不是同一张（一个小算例：Linux 617 个节点，Windows 620 个）。
  所以同一批数据的网格要在同一台机器上划。现在建模、划网格、Abaqus 都在 Windows，worker 上只跑代理的训练。
- 锁里没有 torch。要上 GPU 的模型，得先把 torch 加进 `pyproject.toml` 和锁、两边重装，这要你来定。

## 二 内核的入口和依赖（查到的）

旧系统的 FE 内核是 M1-3406-v1，代码哈希 `6d7af243d0`（8 个文件的原始字节按固定顺序算的 SHA-256，取前 10 位）。
这 8 个文件一个字节不动地打进内核包；包怎么打写在 `external/kernel_m1_3406/`：

    python external/kernel_m1_3406/build.py <旧系统的 mobo_toy> <包的文件夹>

- 入口：`jobs.prep`（建模）、`run_abaqus.run_and_export`（求解和导出）、`jobs.fric_only_result` 和 `stability.stability`（后处理）、`post_m1.lame`（Lamé 对照）。
- 依赖：numpy 2.5.3、scipy 1.18.1、gmsh 4.15.2、shapely 2.1.2、contourpy 1.4.0、PyYAML 6.0.3、matplotlib 3.11.2，都写进了 `pyproject.toml`；求解要 Abaqus 2025。
- 包会五种做法：`template`（只模板化）、`build`（建模）、`post`（后处理）、`bench`（Lamé 对照）、`selfcheck`（自检，几秒钟）。
- 在这台 Windows 上实测过：模板化、建模（31 秒）、Abaqus 求解（1007 秒）、后处理都走通，和旧数据库里同一个设计的那一行对得上（见第四节）。

一个顺带查出来的坑：`gmsh.initialize()` 会把所在进程的 PATH 截短，之后那个进程找不到 git。读 STEP 的地方用完都把 PATH 放回去了（`plugins/recon/sources.py`）。

## 三 “不收敛”和“网格失败”算不算结论（定的）

**定的：都不算结论，归“待查”；只有拿得出物理证据的不收敛才算结论。** 结局表在 `plugins/fea/outcomes.py`：

| 结局 | 类别 | 什么时候 |
| --- | --- | --- |
| `finished` 算完 | 算出来了 | |
| `misfit` 放不进去 | 结论 | 模板化说这个设计在这根骨里放不下 |
| `unstable` 松动 | 结论 | 不收敛，**而且**有证据：压配和释放两步已经算完，停在加载步里，停下前最后一个收敛的增量上界面切向相对位移的面积加权 95 分位已经超过 150 µm |
| `not_converged` 不收敛 | 待查 | 没有上面那种证据的不收敛 |
| `mesh_failed` 网格失败 | 待查 | |
| `error` 出错 | 待查 | 内核自己崩了、结果读不出来 |
| `env` 环境问题 | 可重试 | 许可证、机器重启 |

另加一条提醒：一轮里数值上没算出来的作业（不收敛加网格失败）不少于 2 个而且超过 5%，记一条问题——先查模型，别让选点绕着走。

依据：

- 旧项目自己的数：v0.14 里 14 个网格失败（1.0%，零散分布，最优点附近也有，研究记录里的判断是“不是力学失败”）、8 个不收敛（都是 L ≤ 26.6 mm，可重复；其中一个放宽后算出来是 19° 的转动、93% 的界面张开）。也就是说网格失败是数值的事；不收敛里有一部分背后是真的松动，但要有证据才能这么说。
- 文献里这类失败叫“隐藏约束”：它是“设计 × 数值设置”的性质，不是设计本身的性质，不该直接记成不可行（Le Digabel & Wild 的约束分类；Sacher 等 2018 和 Bachoc 等 2020 把“算不出来”单独建一个分类模型；Bussemaker 等 2024）。把它当成不可行喂给选点，等于让优化器躲开数值上难算的区域。
- 150 µm 这条线：超过它骨长不上去，初期稳定性的研究普遍拿它当阈值（Al-Dirini 等 2019 的 1952 例虚拟试验用的就是 150 µm 和 7000 µε）。载荷没加满就已经松到这个程度，加满只会更松，所以这个设计的结论不依赖数值收敛。

蓝图里这两个结局本来就是“先归待查”，这里没有改它，只是多分出了有证据的 `unstable` 和内核出错的 `error`。

“同一根骨的角度只有在同一种定义下才能比”，所以每个标志点的定义跟着点一起存在骨模型里；自动找法换了，定义的文字也要换。

### 代理

留出误差用 log10 上的均方根差（dex）。FE 自己的噪声底大约 0.012 dex，再准也准不过它。

| 留出误差 | 判定 |
| --- | --- |
| ≤ 0.05 dex，R² ≥ 0.9 | 好 |
| ≤ 0.10 dex，R² ≥ 0.8 | 能用，下结论要拿 FE 复核 |
| > 0.15 dex | 不能用 |
| 往外推的那一组：≤ 0.10 能往外推；≤ 0.20 有限度，要 FE 确认；再大不行 | |
| 名义 95% 的区间，实际覆盖率 | 0.90 到 0.99 |

线要在结果出来之前登记：它们写在训练设定里（`acceptance`），训练设定是存定的输入，误差报告里由代码逐条判。

依据：Al-Dirini 等 2020 的 GP 代理在 1036 个方案上 RMSE < 20 µm、拟合优度 0.81；Cilla 等 2017 用机器学习代理做短柄优化。
0.05 dex 约等于 12% 的相对差，是“能分清两个设计谁好”的量级；0.15 dex 约 41%，已经和设计之间的差别一样大了。

**现在的实际情况（要如实说）**：拿旧数据库 v0.14 转来的 1144 行训练（882 行训练、262 行留出），现在自带的模型——二次多项式岭回归的自助集成，
只用 numpy——首次转动的留出误差是 0.166 dex（R² 0.960），可恢复微动是 0.228 dex（R² 0.942），区间覆盖率 0.98。
照上面的线，这是“不能用”。区间是老实的，流程是通的，但模型本身不够好。`plugins/surrogate/models/` 是自由的，换模型不换评价：
换一个更好的模型（比如高斯过程）之后，拿同一条线量它就行。
