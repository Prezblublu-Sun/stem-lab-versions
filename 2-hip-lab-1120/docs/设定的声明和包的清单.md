## 二、设定的声明

### 一项怎么写

| 字段 | 必有 | 说明 |
| --- | --- | --- |
| 名字 | 是 | 机器认的名字：字母开头，字母、数字、下划线。一份声明里不能重名 |
| 叫法 | 是 | 给人看的名字，比如“摩擦系数” |
| 含义 | 是 | 一两句话：这个量是什么，影响什么 |
| 分组 | 是 | 页面上放在哪一组。有限元的照 Abaqus 分组：材料和截面、网格、相互作用、约束、分析步、边界条件、载荷、初始条件、输出、作业和求解控制 |
| 类型 | 是 | 见下一小节 |
| 单位 | 数和向量必有 | 从单位表里选（补，见下）。不在跑的时候换算 |
| 范围 | 数必有 | 最小、最大，各自含不含端点 |
| 可选的值 | 几选一、几选几必有 | 每个值带一个给人看的叫法 |
| 只在什么时候有 | 可选 | 只在某一项取某几个值时，这一项才有。比如“摩擦系数”只在切向是罚摩擦或拉格朗日时有 |
| 每个点能不能变 | 是 | 能变的项，在一份设定里可以写“每个点给”，由一批点逐个给出（就是现在的“条件”） |
| 必不必填 | 是 | 可选的项，设定里不写就是“没有”，不会被补成默认 |
| 测试轮的取值 | 是 | 只用来拼测试轮的设定，页面也可以拿它当初始填法。正式的设定要写全、要登记，不靠它 |
| 测试轮取值的来路 | 是 | 这个数从哪来：Abaqus 手册、文献、厂家资料、原项目（注明是哪一版的什么） |
| 对应 Abaqus 的 | 可选 | 对应的关键字和参数，比如 `*FRICTION`、`ELASTIC SLIP`。只给人看，核心不管；求解器不是 Abaqus 时可以不写 |

### 类型

| 类型 | 说明 |
| --- | --- |
| 数 | 带单位和范围 |
| 整数 | 带范围 |
| 是否 | 开或关 |
| 几选一 | 从可选的值里选一个 |
| 几选几 | 从可选的值里选几个 |
| 文字 | 可以带一个写法的规矩，比如只许字母和数字 |
| 三维向量 | 带单位；可以要求长度为一，用来写方向 |
| 表 | 若干行，每一列又是声明过的一项。比如分析步的序列（每一步：名字、做什么、NLGEOM、时长、增量），或者限深的曲线（位置、上限），或者工况表（每种活动的关节力和姿态） |
| 登记的东西 | 指向登记里某一种东西，比如“用哪一份 CT”“用哪一份标定”“用哪一份预测” |
| 名字引用（补） | 指向某一份输入里一个有名字的东西，用来写“输入的位置”，比如力加在哪个点上、推导量在哪个面上取。可以指向：骨模型的块、关节、区域、面、标志点；柄的模型的区域、面组、特征点、轴。启动前照实际的输入核对，名字不存在就拒 |

### 单位表（补）

| 量 | 单位 |
| --- | --- |
| 长度 | mm；微动、间隙这类小量用 µm |
| 面积、体积 | mm²、mm³ |
| 力、力矩 | N、N·mm |
| 应力、模量 | MPa |
| 柔度 | MPa⁻¹ |
| 刚度 | N/mm |
| 比表面积、曲率 | mm⁻¹ |
| 质量 | kg |
| 密度 | g/cm³ |
| 角度 | 度 |
| 时间 | s |
| CT 值 | HU |
| 无量纲、比例 | 1（比例写小数，不写 %） |

- 单位从这张表里选。同一个量在各处用同一个单位，比如微动一律 µm。
- 跑的时候不换算。导入外面的东西时换算，换算记进记录。
- 表里要加单位，就要改契约。

### 例子：有限元包声明里的两项

```
{"名字": "tangential", "叫法": "切向行为", "分组": "相互作用", "类型": "几选一",
 "可选的值": [{"值": "frictionless", "叫法": "无摩擦"}, {"值": "penalty", "叫法": "罚摩擦"}, {"值": "lagrange", "叫法": "拉格朗日"}],
 "每个点能不能变": false, "必填": true, "测试轮的取值": "penalty", "来路": "原项目 M1 的做法", "对应 Abaqus 的": "*FRICTION"}

{"名字": "mu", "叫法": "摩擦系数", "分组": "相互作用", "类型": "数", "单位": "1", "范围": {"最小": 0, "最大": 1},
 "只在什么时候有": {"tangential": ["penalty", "lagrange"]},
 "每个点能不能变": true, "必填": true, "测试轮的取值": 0.3, "来路": "文献：钛合金对松质骨的常用值", "对应 Abaqus 的": "*FRICTION 的摩擦系数"}
```

例子里的字段名用中文，只为了好读；真的格式用英文的键。

### 一份声明

- 有一个名字，比如“设计项”“放置设定”“有限元设定”“推导量设定”“重建设定”“超参数”“策略参数”“运行设定”。
- 版本跟着包或插件走；声明的内容有一个哈希，设定里会记下它。
- 项的列表，加上分组的顺序。
- 跨项的核对只有两种：“只在什么时候有”，和两项之间的大小关系（比如最小值小于最大值）。更复杂的核对交给包或插件自己的检查动作，但项的名字、单位、范围只认声明。

## 三、设定（登记的值）

### 写什么

| 写什么 | 说明 |
| --- | --- |
| 照哪份声明 | 包的编号和声明的哈希，加上声明的名字；运行设定则是实验类型和插件的版本 |
| 用途 | 正式，或测试 |
| 每一项的取值 | 写全：必填的都有，可选的不写就是“没有” |
| 每个点能变的项 | 要么一个值，所有点都一样；要么写“每个点给” |
| 每一项的来路（补） | 这个值从哪来：文献、测量、厂家资料、照测试轮的取值、原项目（注明哪一版的什么）。正式的设定要不要每一项都写，见第十一节 |
| 说明 | 这一份是做什么用的，从哪一份改来的（可选） |

### 核心怎么核（固定的规则，只有这一份）

1. 照的那份声明存在，而且就是这个实验填的那个包的。声明的哈希对得上。
2. 声明里没有的项不许出现。
3. 必填的项都在；“只在什么时候有”的项，条件不满足时必须不出现，满足时照必不必填来。
4. 类型对、单位对（就是声明的单位）、在范围里、在可选的值里。
5. 两项之间的大小关系成立。
6. 写了“每个点给”的项，这一批点的每个点上都有，而且照同一份声明核对。有限元设定、放置设定、推导量设定里的都算。
7. 测试用途的设定不能用在正式的轮上，反过来也不行。
8. 名字引用的名字在实际的输入里存在（补）。

不合的在启动前被拒，并说出是哪一项、哪一条规则。

### 例子：一份有限元设定

```
{"照哪份声明": {"包": "R0123", "声明": "有限元设定", "哈希": "…"}, "用途": "正式",
 "取值": {"tangential": "penalty", "mu": "每个点给", "element": "C3D10", "mesh_interface_mm": 1.0,
          "load_point": {"名字引用": "柄的模型.特征点.taper_center"},
          "steps": [{"名字": "release", "做什么": "消过盈"}, {"名字": "load", "做什么": "加载"}, …], …},
 "来路": {"mu": "文献 …", "element": "Abaqus 手册 …", …}}
```

### 改设定和改声明

- **改设定**：登记新的一份。旧的那份不动，用过它的结果照样追得到它。
- **包的新版本改了声明**：旧的设定不自动沿用。要照新的声明重新登记。页面可以把旧值搬过去，搬的时候照新声明核一遍。

## 四、一批点（补：改写）

- **写明照什么写的**：柄空间包（或者明说无植入物）、有限元设定、放置设定、推导量设定。
- **每个点 = 设计项 + 每个点给的取值**：
  - 设计项：柄空间包声明的，写全；无植入物时没有。
  - 每个点给的取值：上面几份设定里写了“每个点给”的项，分三组写（有限元的、放置的、推导量的），每组写全。
- **放置设定和推导量设定里也可以有每个点能变的项**：
  - 放置的，比如“截骨面比参考低多少”，有领柄和无领柄比较时，它正是主要的自变量；
  - 推导量的，比如“分哪几个区、阈值多少”。
- **每个点的哈希**：由主体标识、设计、所有“每个点给”的取值算出来。仍然是用写全的东西算，只是多了放置和推导量两组。
- 登记时核一遍，启动时照这个实验填的包和设定再核一遍。

## 五、身份：每个数是怎么来的（补，新的一节）

**规矩**：影响算出来的数的每一样输入，要么在点的哈希里，要么在数据的 `made_by` 里。两样都相同的数，才能混在一起用。

- **点的哈希管“这个点”**：主体、设计、每个点给的取值。
- **`made_by` 管“怎么算的”**：

| 进 `made_by` 的 | 说明 |
| --- | --- |
| 柄空间包，和放置设定里所有点都一样的那部分 | 无植入物时写明“无” |
| 有限元包，和有限元设定里所有点都一样的那部分 | |
| 推导量定义包，和推导量设定里所有点都一样的那部分 | |
| 骨模型的那一版（登记的编号） | 同一根骨重建出新的一版，算出的数会不一样，`made_by` 也就不一样 |
| 用到的预测（登记的编号） | 比如拿一份预测的场当柄的材料 |

- **不进 `made_by` 的**：运行设定，它只管怎么跑。
- **现在缺的**：放置设定、推导量设定、骨模型的版本、用到的预测，都不在点的哈希里，也不在 `made_by` 里。换了这些，算出的数照样同哈希、同 `made_by`，会被当成同一份混用（四篇文献推演第三节第 2 条）。

## 六、包的清单

### 每个包都有的

| 段 | 写什么 |
| --- | --- |
| 身份 | 包的种类、名字、版本、和上一版比改了什么。代码的哈希由核心登记时算，不由包自己写 |
| 外部程序 | 用到的外部程序及其确切的版本，比如 Abaqus 2025。没有就空着。装在哪不写在包里：写在机器清单里（每台机器的 `programs`：名字、版本、位置），叫包的一方照名字和版本找到位置交给包（2026-11-18 加的） |
| 入口 | 怎么起它：命令、参数（现在的格式已经有） |
| 声明的设定 | 一份或几份声明（第二节） |
| 对输入的要求 | 要骨模型的什么（见《骨模型的写法》第五节）、要柄的模型的什么、要数据的哪些列、要别的包交来的什么 |
| 产出 | 每一列、每个场：名字、单位、含义、场是哪一种（第六节“场的写法”）；交出来的东西是哪一种 |
| 能做的事 | 这个包支持哪些动作（见下表） |
| 测试轮 | 一份参照输入（包里带的，比如一根造的假骨、一个设计点），或者写明用账里的哪一样 |
| 自检 | 样本和容差（现在的格式已经有）：第一次在一台机器上用时先跑一遍 |

### 各种包各有的

| 包 | 声明的设定 | 对输入的要求 | 产出 | 能做的事 |
| --- | --- | --- | --- | --- |
| 柄空间 | 设计项（每一项都是每个点给的；目录式的柄空间只有一项“型号”）；放置设定：截骨的参考、截骨面的高低、放柄的规则、入口、对线、插入深度等，可以有每个点能变的项 | 骨模型的标志点、表面、区域、覆盖范围 | 柄的模型（补，见下一小节）；模板化的量 | 模板化：放不放得下、去多少骨，不做有限元；出柄的模型：给有限元包和推导量定义包用 |
| 有限元 | 有限元设定（照 Abaqus 分组，标明哪些每个点能变；用名字引用骨和柄的区域、面组、点） | 骨模型：几何的种类、维度、材料模型；或者声明不要骨模型（补，只有柄、单胞这类分析，要你定）。柄的模型：支持哪些材料给法（均匀、分段、按场）；或者明说无植入物（补） | 标签（标量）；场（规则数组或点集）；建模时就有的场，比如积分点的坐标（补）；原始结果的归档 | 建模（写出求解器的输入和求解的命令）、后处理、对照算例（比如 Lamé 压配）、自检 |
| 推导量定义 | 推导量设定：参数，包括取值的位置（名字引用：哪个面组、哪个区、哪个点）；可以有每个点能变的项（补） | 骨模型和柄的模型里引用到的名字；有限元产出的场和标签 | 推导量的列 | 算推导量 |
| 重建方法 | 重建设定；每个区域的材料；标志点的找法 | 能收哪种骨源：CT 加外形、STEP、STL、现成的体网格（补） | 骨模型（照《骨模型的写法》）；量出来的数，供检查门的线引用 | 出候选、定稿 |
| 代理模型 | 超参数 | 数据的列：能学标量还是场（规则数组、点集，补）；行数的范围；要不要 GPU | 预测器（现在的格式） | 训练 |
| 选点策略 | 策略的参数 | 要不要数据、要不要预测器（现在的 `needs`） | 选出的点和理由 | 选点 |
| 预测器 | 无（它是训练出来的） | 适用范围（现在的格式）；点集的场，预测时要给点的坐标（补） | 预测 | 出预测、自检 |

### 柄的模型（补，新的小节）

柄空间包交给有限元包和推导量定义包的东西，照骨模型的样子写：

| 段 | 写什么 |
| --- | --- |
| 区域 | 每个区域：名字、角色（柄体、多孔段、涂层、领、锥颈……）、几何文件：三维实体、二维区域、或者现成的体网格 |
| 材料 | 每个区域一种给法：均匀的（照 Abaqus）；分段的（几段各一组参数，参数可以就是设计项）；按场给的（比如一份预测的密度场，加从密度到模量的关系，用了哪一份预测记进 `made_by`） |
| 命名的面组 | 领的承压面、涂层区、多孔区的表面、锥颈等。有限元设定里的接触、绑定、过盈都用名字引用它们 |
| 特征点和轴 | 锥头中心（关节力打在哪）、柄轴、柄尖、肩、领平面等。推导量定义也能用，比如照柄轴和柄尖划 Gruen 区 |
| 放置 | 在骨的坐标系里的姿态；截骨面；去掉的骨的范围；用到了骨模型的哪些标志点（姿态和截骨面写在骨模型文件自己的坐标里，2026-11-19 定的） |
| 模板化的量 | 入口偏移、选的号、贴合比例、去骨量等 |

- **目录式的柄空间**（商品柄）：设计项是“型号”，每个型号对应一份现成的柄的模型，比如有领、同形无领两份 CAD。
- **无植入物**：明说“无”，有限元设定里就没有柄的那几组。四篇里关节软骨那篇就是这样。

### 包和包之间交接的东西（契约里固定的格式）

| 从 | 到 | 交什么 |
| --- | --- | --- |
| 柄空间 | 有限元、推导量定义 | 柄的模型（上一小节），或者明说无植入物 |
| 重建方法 | 用骨模型的一方 | 骨模型（照《骨模型的写法》） |
| 有限元 | 推导量定义 | 标签和场，照有限元包的产出声明；场可以是点集 |
| 有限元 | 代理 | 建模时就有的场（比如积分点的坐标），可以当特征（补） |
| 代理模型 | 代理、优化 | 预测器（现在的格式） |
| 预测器 | 柄空间、有限元 | 预测的场当某个区域的材料（按场给）；用了哪一份预测记进 `made_by`（补） |

有了这几样固定的交接格式，任何一个柄空间包都能配任何一个有限元包用。只要声明对得上，不用为某一对包写专门的代码。

### 场的写法（补，新的小节）

- **两种场**：
  - 规则数组：每一行形状都一样。现在只有这一种。
  - 点集：每一行是一组点，点数可以不同，每个点带坐标和值。网格随设计变的场（比如柄内多孔的密度）只能写成点集。
- **建模时就有的场也是场**：比如积分点的坐标，可以当代理的特征。
- **点集的场怎么学**：预测器学点集的场时，输入可以带点的坐标；预测时给坐标，出值。
- **要改的地方**：数据和预测的格式（契约），以及代理冻结的误差算法（点集的预测和真值怎么对齐、怎么算误差）。

## 七、插件声明的运行设定

运行设定只管“怎么跑”，不影响算出来的数：

| 实验 | 运行设定 |
| --- | --- |
| FEA | 求解槽、建模和后处理的并发数、各步的超时、归档放在哪 |
| 重建 | 超时 |
| 代理 | 在哪台机器上训练、超时、心跳的间隔 |
| 优化 | 超时 |

运行设定的身份记进来历，但不进数据的 `made_by`。

## 八、对照和实测数据（补，新的一节）

### 登记过的对照

不同 `made_by` 的数原则上不混在一起用。要混用，先登记一份对照：

| 写什么 | 说明 |
| --- | --- |
| 比的是哪两样 | 两个 `made_by`，或者两份数据 |
| 比了什么 | 哪几列、在哪些点上 |
| 怎么算差 | 用什么指标、容差多少、容差的来路 |
| 在什么范围里成立 | 设计和条件的范围 |
| 结论 | 在这个范围里可以一起用，或者不可以 |
| 谁定的、什么时候 | |

它是一份报告，登记以后不变。代理训练时要混用两种 `made_by` 的数据，就要填这一份；范围之外的行不收。

### 实测数据

- **是什么**：在系统外测出来的数，比如打印的样件上贴应变片测的应变、体外实验测的微动。
- **写什么**：
  - 每一列的名字、单位、含义；
  - 测的是哪个设计，或者样件对应哪个点；
  - 怎么测的：仪器、方法、标定；在哪测、什么时候测的；
  - 不确定度。
- **用处**：和有限元的结果比（复核），当作一份证据；不能当成有限元算的数去训练。
- **要改的地方**：契约里要加一种东西（要你定）。

## 九、测试轮怎么用这些

- **测试轮的设定**：把每份声明的“测试轮的取值”拼成一整套，登记成测试用途。
- **测试轮的输入**：包带的参照输入，或者包里写明的账里的那一样。
- **测试轮的产物**：标成测试，不进正式的数据，不能拿来训练和选点。

## 十、和现在的差别

- **内核清单**：现在的设计项和条件只有名字、单位、含义；没有类型、范围、测试轮的取值和来路，也不标哪些每个点能变，没有和 Abaqus 的对应。
- **设定**：九样设定都是没有声明的 JSON。FEA 的导出设定还把运行设定和交给内核的设定混在一起。
- **包的清单**：现在只有入口、自检、容差，加上内核的几样声明；没有对输入的要求，没有测试轮。
- **交接**：柄的几何和有限元模型在同一个包里，没有交接的格式，也没有“柄的模型”这一样（补）。
- **身份**：点的哈希和 `made_by` 漏了放置设定、推导量设定、骨模型的版本、用到的预测（补）。
- **场**：只有规则数组（补）。
- **单位**：只有寥寥几个（补）。
- **对照和实测数据**：都没有（补）。

## 十一、要你看的、要你定的

1. 类型够不够，要不要加别的。
2. 跨项的核对只有“只在什么时候有”和大小关系两种，更复杂的交给包自己的检查动作。这样行不行？
3. 包的新版本改了声明，旧设定要重新登记，不自动沿用。我建议这样。
4. 运行设定不进 `made_by`：它只管怎么跑，不影响算出来的数。这样行不行？
5. 一批点写明照哪个柄空间包，和哪几份设定（有限元、放置、推导量）写的。这样点和设定就绑在一起了：换了“每个点给”的项，就要另登一批点。
6. 正式的设定是不是每一项都必须写来路（补）。我建议必须，可以写“照测试轮的取值”，指到包里的来路。
7. 契约里加两种东西：“对照”（可以算报告的一种）和“实测数据”（补）。
8. 点集的场：第一版就做，还是先在格式里留位置（补）。
9. “名字引用”这种类型：用它写“输入的位置”，行不行（补）。
