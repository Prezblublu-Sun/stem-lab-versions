# 改格式的分批（第 2、3 步，2026-11-16 起）

**依据**：三份草案，《核心、插件和包》《设定的声明和包的清单》《骨模型的写法》；你 11-16 说的“照现在的设定继续”；《搭建方法》第四节的计划。

## 为什么第 2、3 步合起来分批做

格式一改，产出它、用它的冻结代码要一起改，不然检查过不了：
- 一批点、made_by 一改，FEA、优化、代理的冻结文件都要跟着改；
- 骨模型一改，重建的冻结文件要跟着改。

所以一样格式算一批。每批走同一条路：
1. 写目标和证明它的测试；
2. 改契约，和用到它的冻结代码；
3. 跑完整检查；
4. 你看固定部分的改动，重新生成清单；
5. 分两次提交。

旧格式都照样读：写升版的函数，旧的账不用重做。

## 六批

| 批 | 做什么 | 动到的固定部分 | 旧的怎么办 |
| --- | --- | --- | --- |
| A | 设定的声明和登记的设定：类型、单位表、名字引用、核验的规矩、测试轮的取值 | 契约新加一个文件和它的测试；核心先不调用 | 没有旧的 |
| B | 柄的模型，和包与包之间交接的格式 | 契约新加 | 没有旧的 |
| C | 包的种类和包的清单：柄空间、有限元、重建方法、代理模型；每个包写声明的设定、对输入的要求、产出、测试轮 | 契约的种类表和包的格式，登记 | 旧的内核包照旧读，留作参照包 |
| D | 一批点第 2 版（放置、推导量两组也能每个点给），和 made_by 第 2 版；核心启动时照声明核验设定 | 契约的一批点和清单，FEA、优化、代理的冻结文件，核心的启动 | 旧的点哈希不变，旧的 made_by 照旧认 |
| E | 骨模型第 2 版 | 契约的骨模型，重建的冻结文件 | 旧骨模型读成一块骨、两个区域 |
| F | 场的点集写法、对照、测试用途的标记 | 契约的数据和清单 | 旧数据照旧读 |

A、B 是纯加的，不动现有的东西；从 C 开始，每批都会动到冻结的插件文件。拆内核（第 4 步）在 C、D 之后。

## A：设定的声明和登记的设定

**目标**：草案第二、三节的声明和设定写得出、核得了。核验的规矩只在契约这一处：`stemlab/contract/formats/declaration.py`。

**怎么算达到**：
1. **声明自己要合规矩**：项名、类型、单位、范围、可选的值、“只在什么时候有”、表的列、测试轮的取值和来路，哪一处不对，说出是哪一项。
2. **设定的九条规矩，每条都有反向测试**：造一份只违这一条的设定，它被拒，说出是哪一项、哪一条。草案第三节的八条，加上“正式的设定每项写了来路”。
3. **测试轮**：任何一份合规矩的声明，拼出来的测试轮设定一定过核验。用属性测试，随机生成声明来试。
4. **变异测试**：改了的规矩要被测试抓到。

**这一批不做**：核心启动时还不调用它，D 批才接上；页面也还不照它画，那是第 9 步。

**照现在的设定定下的几处**（不对就说）：
- **单位表**：ASCII 写法，和现有的包一致。

  | 量 | 写法 |
  | --- | --- |
  | 长度 | `mm`、`um` |
  | 面积、体积 | `mm2`、`mm3` |
  | 力、力矩 | `N`、`N*mm` |
  | 应力、模量 | `MPa` |
  | 柔度 | `1/MPa` |
  | 刚度 | `N/mm` |
  | 比表面积、曲率 | `1/mm` |
  | 质量 | `kg` |
  | 密度 | `g/cm3` |
  | 角度 | `deg` |
  | 时间 | `s` |
  | CT 值 | `HU` |
  | 无量纲、比例 | `1` |
- **每个点给**：写成 `{"per_point": true}`。
- **名字引用**：写成 `{"ref": "bone.region.cortical"}`，依次是哪一份输入、哪一类、叫什么。
- **“只在什么时候有”的限制**：只能看一项每个点都一样的几选一或是否。不然一项在不在，要到每个点才知道。
- **来路**：正式的设定，每个写了的项都要写来路。测试轮的设定，来路就是声明里测试轮取值的来路。

A 批 2026-11-16 提交：`25a34eb`。

## B：柄的模型，和共用的材料写法

**目标**：柄空间包交给有限元包、推导量定义包的“柄的模型”，写得出、核得了。任何一个柄空间包，都能配任何一个有限元包用。
材料的写法单独一份，柄的模型和以后的骨模型第 2 版（E 批）共用。都在契约里：
- `formats/material.py`
- `formats/stem_model.py`

**怎么算达到**：
1. 草案里柄的模型的六段（区域、材料、命名的面组、特征点和轴、放置、模板化的量）都写得出。不合的说出是哪一段、哪一项。
2. 材料的七种给法，每种参数的规矩各有一个反向测试。
3. 四篇文献里用到的都能写，各写一条测试：
   - 有领柄和同形无领柄（目录式）；
   - 八段梯度多孔柄（沿柄轴分段）；
   - 预测的密度场当材料（按场给）；
   - 软骨的 neo-Hookean（超弹性）。
4. 变异测试。

**这一批不做**：
- 现有的内核和插件还不用它，第 4 步拆内核时才接上；
- 柄的模型从哪来，记进 made_by，是 D 批的事。

**照现在的设定定下的几处**（不对就说）：
- **不进账**：柄的模型只在一次作业里，由柄空间包交给有限元包和推导量定义包。文件夹里放清单 `stem_model.json` 和几何文件。
- **无植入物**：不交柄的模型，作业里写 null。
- **材料的单位**：照单位表。
  - 模量、C10、C01 用 MPa；
  - D1 用 1/MPa；
  - 密度用 g/cm3；
  - 长度用 mm。

  写成剪切模量 G、体积模量 K 的 neo-Hookean，导入时换成 C10 = G/2、D1 = 2/K。
- **分段的材料**：沿一根轴，各段首尾相接、不重叠；每段一种均匀的给法。各段有各自的几何时，就写成几个区域。
- **命名的面组**：一组一个表面片文件，落在某个区域的边界上。
- **放置**：
  - 柄的坐标系在骨的解剖坐标系里怎么摆：原点加三个轴，两两垂直、长度为一、右手系；
  - 截骨面：一点加法向；
  - 去掉的骨：一个实体文件，可以没有；
  - 用到了骨模型的哪些标志点。
- **区域的角色**：先定柄体、多孔段、涂层、领、颈、锥、其他。

- **格式版本**：柄的模型在 `versions.FORMATS` 里登了第 1 版。`tests/contract/test_versions_machines_layout.py` 把“契约里有哪几种格式”写成了一张固定的单子，所以跟着加了这一项。

B 批 2026-11-16 提交：`4895e05`。

## C：包的种类和包的清单

**目标**：草案里的几种包都登记得了，每个包都写明以下几样，契约照它核：
- 用到的外部程序；
- 声明的设定；
- 能做的事；
- 对输入的要求；
- 产出；
- 测试轮用的参照输入。

**怎么算达到**：
1. 种类表加四种包，都是带代码的包，用同一种格式：
   - 柄空间 `stem_space`
   - 有限元 `fem`
   - 重建方法 `recon_method`
   - 代理模型 `surrogate_model`

   原来的内核 `kernel` 留着，作参照包（M1-3406-v1）。
2. 包的清单升到第 2 版。新加的几段，新的四种必写；原来的四种可以写，也可以不写；旧的第 1 版清单照样读。
3. 新加的每一段，写错都有反向测试，说出是哪一段。声明的设定照 A 批的规矩核。
4. 变异测试。

**新加的几段**：
- `programs`：用到的外部程序和确切的版本，`[{"name", "version"}]`，比如 Abaqus 2025。没有就不写。
- `declarations`：声明的设定，用 A 批的写法，一个包里不重名。各种包至少要有这几份：
  - 柄空间：`design`（设计项）、`placement`（放置）；
  - 有限元：`fem`；
  - 重建方法：`rebuild`（不用插件的名字 `recon`：核心不许出现插件的名字，守护测试会拦）；
  - 代理模型：`hyper`（超参数）。
- `modes`：能做的事。
  - 柄空间：`template`（模板化）、`model`（出柄的模型）；
  - 有限元：`build`（建模）、`post`（后处理）；
  - 重建方法：`draft`（出候选）、`finalize`（定稿）；
  - 代理模型：`train`。
- `inputs`：对输入的要求，`{输入名: {…}}`。里面具体写什么，由用它的冻结代码核；骨模型、柄的模型的要求在 D、E 批补上。
- `outputs`：产出的列，`[{"name", "unit", "meaning", "role"}]`，role 用数据的那几种。
- `test_round`：测试轮用的参照输入，`{"inputs": {输入名: {"folder": 包里的文件夹} 或 {"item": 登记的编号}}}`。

**不再写“十六种”**：种类多了，提示改成“登记的种类里没有 …”。三条固定的测试守着原来的提示和单子，跟着改：
- `tests/contract/test_kinds.py`
- `tests/contract/test_formats.py`
- `tests/blocks/test_registry.py`

**蓝图**：蓝图第三节的种类表还写着十六种。草案说蓝图先不改，所以这一批不动它，要不要改由你定。

## D 以后

每批开工前，在这里补上它的目标和测试，再动代码。

**D 批要定的一处**（B 批时记下的）：登记的设定，它的写法也要有版本号。现在设定是一个值，没有自己的格式版本；接进核心之前补上。
