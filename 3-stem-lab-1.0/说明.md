# stem-lab 1.0 说明

一个操作台加一个仪表盘。只用 Python 3.12 的标准库，不用装任何包。

## 怎么开

- 双击 `start.bat`：开一个黑窗口，并打开浏览器到 http://127.0.0.1:8765/ 。关掉黑窗口就关了页面；在跑的实验不受影响，再开页面照样看得到。
- 或者在命令行里：`python -m stemlab`。`--port 8766` 换端口；`--data D:\lab-data` 换数据放的地方（默认是这里的 `data\`，不进 git）。数据目录的路径最好只用英文，以后 Abaqus 要在里面跑。
- 只听本机，别的电脑连不上。

## 第一次用

到“登记的东西”里登记（路径可以写相对这个文件夹的）：

| 类型 | 名字 | 路径 |
| --- | --- | --- |
| 做法 | 不用写 | `methods/recon_demo`、`methods/fea_demo`、`methods/surrogate_demo`、`methods/optimize_demo`（各登记一次） |
| CT | 示例CT | `examples/ct_demo.txt` |
| 骨 | 示例骨 | `examples/bone_demo.json` |
| 点 | 示例点 | `examples/points_demo.csv` |
| 结果 | 示例结果 | `examples/results_demo.csv` |
| 模型 | 示例模型 | `examples/model_demo.json` |

然后点“新建实验”。四个示例做法**只是示例，不是科学**：公式是随手写的，只为把六步走通。`examples/settings_demo.json` 可以拿来试“从一份外来的设置填表”。

## 页面五处

- **仪表盘**：在跑的（完成数/总数、正在干什么、多久没动静）；哪里停了（最后的进度、日志末尾、退出码；看护进程不在了就显示“中断”）；最近跑完的和判定。每 3 秒刷一次，页面不在前台就不刷，不起任何进程。
- **新建实验**：选哪一类（重建、FEA、代理、优化，加上做法里写的别的类）→ 选做法和要用的东西（下拉框不替你默认选）→ 填设置（每项有默认值和范围；可以从外来的 JSON 或 TOML 填表，认不得的项会列出来）→ 写门槛（可以不写）→ 封存并启动。
- **实验和结果**：列表；点开一个，看判定、它用了什么、产出、结果表、日志、目录里的文件；可以停下、继续、照这个再开一个。
- **登记的东西**：按类型列出每样东西、从哪来、留底在哪、来历。外来的东西和做法分“第几版”；实验的产出不排版本，写它是哪个实验的。登记表单也在这里：登记时会抄一份留底。
- **核对**：账本逐行核对（对不上的行都列出来，说清是哪一条），每样登记的东西、每个实验的产出现在和记下时一不一样，还有 data 里有、账本上没有的实验目录和做法留底。账本有对不上的地方时，每一页顶上都会有红字。

## 把一个外来的做法接进来

接一个外来的算法，要照模板写一份说明（`method.toml`）和几行接头的脚本：

1. 照 `methods/template/` 建一个文件夹：`method.toml`（名字、哪一类、命令行、要选的东西、设置项、会报的数）加上要跑的脚本。全部约定写在模板的注释里。
2. 脚本从实验目录的 `task.json` 读选用的东西和设置；往 `progress.jsonl` 追加进度；最后写 `result.json`（报的数、产出、可选的结果表）。产出要放在实验目录里（比如 `out/` 下面），放在外面的不算它的产出。退出码 0 并且有 `result.json` 算跑完。
3. 在“登记的东西”登记：类型写“做法”，路径指向这个文件夹。`method.toml` 缺了必需的项，登记时就会说第几项缺什么。登记时整个文件夹按指纹抄一份留底，实验跑的是留底那份；以后改了文件夹，再登记一次就是新的一版（内容没变，就不会多出一版）。留底被人动过的话，照原处的文件再登记一次就恢复（核对页上有按钮）。
4. 点“继续”是在同一个目录里再跑一次脚本；上一次的 `result.json` 已被改名成 `result.attempt1.json` 之类留着，要不要接着算由脚本自己看。

## 固定的部分

`stemlab/` 一共 1726 行（含页面的 HTML、CSS、JS）。其中**专门守三件事的约 480 行**，要逐行看的是这几段：

| 文件 | 哪几段 | 约多少行 |
| --- | --- | --- |
| `ledger.py` | 除最后的 `State`、`state`（从账本叠出现状）以外的全部：只往后加、哈希链、头、核对、文件锁 | 190 |
| `fingerprint.py` | 全部 | 46 |
| `things.py` | `label`、`where`、`check`、`_keep`（抄留底）、`register` | 75 |
| `runs.py` | `inside`、`judge`、`seal`、`changed_uses`，`start` 开头的几项核对，`finish` | 105 |
| `pages.py` | `check_page`（核对页） | 60 |

其余是页面（`pages.py`、`web.py`）和跑实验（`runs.py` 的其余部分、`__main__.py`），可以随便改。注意：系统的指纹算的是整个 `stemlab/`，改页面上一个字也算换了一个版本，之后的实验页上会照实显示“和封存时不一样”。

测试在 `tests/`（484 行），只测三件事和四类的六步走得通：`python -m unittest discover -s tests`，约 35 秒。

## 三件事落在哪

**记下来的不被悄悄改**
- `ledger.py`：`append` 只往后加，代码里没有改和删；`_digest` 和 `verify` 是哈希链；每加一条，旁边的 `ledger.head` 记下最后一条的编号和指纹，末尾被砍掉或整个换成旧的，一比就知道。`trouble` 让每一页顶上在账本对不上时说出来。
- `fingerprint.py`：`of` 算指纹，`check` 比对并说出哪个文件变了。
- 登记时把外来的东西（做法也是）抄一份到 `data/store/<指纹>/` 留底，记下指纹（`things.py` 的 `_keep` 和 `register`）；实验用的是留底那份，原处以后怎么变都不影响已登记的版本。实验的产出不抄，由跑完时的目录指纹看着。
- 用的时候核对：`runs.py` 的 `changed_uses`。对不上只剩两种：外来东西的留底被人动过，或者实验的产出跑完以后被人改过。新建时（`web.py` 的 `post_new`）不让启动，并分开说：留底被动过的，给“照原处的文件恢复留底”的按钮（原处也改过的话会成为新的一版）；产出被改过的，给“把它现在的样子登记成一样外来的东西”的按钮。继续时（`runs.py` 的 `start`）也不让启动，说清这两种各该怎么办。
- 实验跑完时给整个实验目录记指纹：`runs.py` 的 `finish`。产出必须在实验目录里（`runs.py` 的 `inside`）。每次启动前，上一次的 `result.json` 改名留着，不会被当成这一次的结果（`runs.py` 的 `start`）。
- 同一个实验最多一个看护进程：它从头到尾握着实验目录外的一把锁（`runs.py` 的 `watch`、`ledger.py` 的 `grab` 和 `held`）。第一次启动时实验目录必须是空的。
- 全量核对：`pages.py` 的 `check_page`。

**每个结果追得到来历**
- 封存：`runs.py` 的 `seal`。记下类、标题、每样东西和做法的名字、第几版、指纹，全部设置，门槛，`stemlab/` 自己的指纹，照哪个实验开的。每次启动也记下当时 `stemlab/` 的指纹（`start`），和封存时不一样的，实验页上写明。
- 产出登记时带着来历：`runs.py` 的 `finish` 里 `things.register(..., source={"experiment": n})`。
- 页面上摆出来：`pages.py` 的 `experiment` 里“它用了什么”一段，和 `origin`。

**合格的门槛先写定**
- 门槛写在封存里（`runs.py` 的 `seal`），排在结束记录之前；之后没有入口能改或补。
- 判定由核心在收尾时照封存的门槛算：`runs.py` 的 `judge` 和 `finish`。没写门槛就是“未设门槛”，永远不显示合格。
- “先写定”只管到这个实验自己：门槛写在**这个实验**的结果出来之前。如果同一版做法、同样的东西和设置之前已经跑出过结果、门槛却不一样，实验页的判定旁边会写明（`pages.py` 的 `same_before`），只是摆出来，不挡。
- 判定只是记下来、显示出来，不挡任何事：不合格的产出照样能被选，下拉框里带着标记。

## 一页纸末尾没定的四处，现在这样办

每处只占一个地方，好改：
1. 没有 AI 在旁边也能用：登记东西、登记做法、六步都在页面上；怎么开见上面。
2. 不同做法的数混不混：不设规矩，只在“它用了什么”和选东西的下拉框里把来历摆出来（`pages.py` 的 `origin`）。
3. 来历记到哪一层：连系统自己的指纹也记，封存时和每次启动时都记（`runs.py` 的 `seal` 和 `start` 里的 `system`）。
4. 门槛：不强制写；写了就封存，由核心判定（`runs.py` 的 `judge`）。

## 要知道的

- 没有删除。登记错了，就再登记一版或换个名字。`data\` 里的东西别手改，改了“核对”页会认出来，每一页顶上也会有红字。
- 核对的限度：它防的是悄悄改和误改，不防存心伪造。改了某一行、删掉中间几行、砍掉末尾、把账本换成旧的，都认得出来。认不出的只剩两种，都要存心：连账本旁边的头一起改；或者改了以后把后面每一行的指纹全部重算一遍。
- 收尾要花时间：跑完以后，系统要给产出和整个实验目录各算一遍指纹，产出有几个 GB 时要等一会儿；这段时间仪表盘上照样显示“在跑”。
- 登记外来的东西时会抄一份到 `data/store/` 留底：大文件（比如一整套 CT）登记时要等一会儿，也多占一份地方；每次启动还要核对一遍留底的指纹，也要等一会儿。之后原处的文件随你动，已登记的版本不受影响，旧实验能照原样重算；要用改过的，再登记一次就是新的一版。
- 留底的文件夹只用指纹命名，但单个文件保留原来的文件名：原文件名带中文的话，`data/` 里的路径就会有中文。以后要给 Abaqus 读的文件，名字请用英文。
- 实验之间不自动接；一个实验的产出只是变成了别的实验可以选的东西。
