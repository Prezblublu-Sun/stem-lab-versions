# fea-archive-export

把归档里已有的 FE 作业导出成数据：标签、界面场、整体场。
只读归档，不重算 FE，不连别的机器，不调旧管线的任何代码。

归档指旧数据库的 `db3406\raw` 那样的文件夹：每个作业一个 `<作业号>.tar.xz`，旁边一个 `<作业号>.manifest.json`。

## 报的四样

| | |
|---|---|
| 名字、版本、类别 | `fea-archive-export`，0.1，`FEA` |
| 设置 | 见下表 |
| 任务 | 每个作业一个。阶段名：读归档、标签、界面场、整体场 |
| 产出 | 标签、界面场、整体场、说明 |

| 设置 | 必填 | 怎么填 |
|---|---|---|
| 归档 | 是 | 归档文件夹。填「只记位置」：记位置和哈希，不复制 |
| 作业 | 是 | 作业号的列表；或一个清单文件（一行一个，或 JSON 列表）；或写 `全部` |
| 导出哪些量 | 否 | 从 标签、界面场、整体场 里选，写成列表。不填就三样全导出 |

这一版没有「推导量的定义」这项设置。归档 `result.json` 里已经算好的量原样进标签表，插件自己不新算推导量。

## 产出

| 产出 | 文件 | 内容 |
|---|---|---|
| 标签 | `标签/标签.csv` | 一个作业一行，148 列，带作业的结局。列名沿用旧表里同一个量的名字 |
| | `标签/标签说明.json` | 每列从哪来；旧表 300 列里没导出的列和原因 |
| | `标签/原始json/<作业号>.json` | 归档里每个 json、标记文件、日志的原文，加归档的清单 |
| 界面场 | `界面场/<作业号>.npz` | 有摩擦模型的作业才有。节点对、每一步的相对位移、间隙、接触量、接触力，界面三角形 |
| 整体场 | `整体场/<作业号>.npz` | 有网格或有场的作业才有。网格原样；每一步的位移、反力、应力、应变、应变能 |
| 说明 | `说明/说明.md`、`说明/说明.json` | 两种场的格式；每个作业有什么、缺什么；归档里本来就没有的量 |

读整体场：`fae_core.read_global(路径)` 给出 `{(模型, 分析步, 量): (编号, 数值, 列名)}`。

数值的存法：csv 里读出来的数，存成 float32 再读回来和原数一模一样时存 float32，否则存 float64。不丢任何一位。

## 归档里本来就没有的，这里也没有

- 应力只有等效应力加 s11、s22、s12，没有完整的 6 个分量。
- 应变只有三个主值，没有分量和方向。
- 摩擦模型的应力和应变只有部分分析步有（一般是 RELEASE 和最后一次加载）。
- 粘接模型和完整股骨没有位移和反力，只有加载一步的应力和应变能。
- 每一步只有最后一帧。PRESSFIT 步没有任何场。
- 界面场没有柄坐标系下的位置、到髓腔壁和外表面的距离。这些要股骨几何。
- 标签没有要靠旧管线代码、归档以外的记录、或整个数据版本才能定的列（转动等稳定性列、泡沫厚度、股骨距应变能变化、来源和划分）。

唯一没有导出的归档文件是 `m_fric.inp`（8 个作业有，求解器的输入文件，不是场）。每个作业的清单里写明。

## 出问题时

| 情况 | 怎么记 |
|---|---|
| 归档文件不存在、解不开、哈希和清单对不上 | 这个任务失败，记一条问题。别的作业照常做 |
| 没有清单文件 | 照常导出，记一条问题（没法核对） |
| 场的行数和网格对不上 | 照常导出，这个任务失败，记一条问题 |
| 作业本身是失败的（归档里有 FAILED.json） | 不是问题。任务完成，标签里有失败原因，没有场 |
| 设置用不了 | 记一条问题，实验直接结束，不起任何任务 |
| 后台进程中途不在了 | 记一条问题，自动重新起，最多一共起 3 次；还不行就把没做完的任务记成失败，可以重试 |

## 怎么做的

| 文件 | 是什么 |
|---|---|
| `plugin.py` | 插件本体。把设置整理成计划，起停后台进程，把进度报进实验记录 |
| `worker.py` | 后台进程。一个作业接一个作业地导出，最后汇总。不碰实验记录 |
| `fae_core.py` | 读归档，做标签、界面场、整体场。只有纯函数 |
| `fae_columns.py` | 标签表有哪些列，每列从哪来 |
| `old_columns.json` | 旧表的每一列导出了没有、为什么。由 `make_old_columns.py` 从旧库的 `schema.json` 生成 |

导出放在后台进程里，操作台和值守只看进度。后台进程不开窗口；操作台关掉它接着做，下次刷新时把进度补报上。
停止：先让它自己退出，等不到就结束它，并核对它确实不在了。
暂停：做完手上这个作业后等着。重试：只重做失败的和停掉的。

## 测试

在仓库根上运行：

```bash
PYTHONUTF8=1 PYTHONDONTWRITEBYTECODE=1 python -m pytest plugins/fea_archive_export/tests -q -p no:cacheprovider
```

| 文件 | 测什么 |
|---|---|
| `tests/test_fae_core.py` | 导出核心。用很小的假归档 |
| `tests/test_fae_desk.py` | 经过操作台：新建、启动、刷新、暂停、停止、重试，后台进程真的起起来 |
| `tests/test_fae_real.py` | 验收。拿 10 个真实作业和归档原文、和旧库 v0.14 逐值比。旧库不在时跳过 |

每条「对得上」的测试后面跟一条「改坏一处就对不上」的对照。测试都用临时文件夹，不碰正式的 `experiments/`，不改归档。
