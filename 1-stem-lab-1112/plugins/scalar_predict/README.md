# scalar-predict：用标量预测器对一批点出预测

类别：代理。只在本机 CPU 上算。出预测算一个实验。

**没做的：** 场预测器（整体应变场、界面场）的出预测。这个插件只认"标量预测器 v0"这一种预测器文件。

## 设置（两项，都必填）

| 设置 | 内容 |
|---|---|
| 预测器 | 训练实验（`scalar-train`）的产出"预测器"；或一个外来的同样格式的文件，用"只记位置"填 |
| 一批点 | 和 FEA 吃的是同一种：一行就是骨、设计、条件。JSON 和平的 CSV 表两种都收。可以是文件，也可以直接填 JSON 的值 |

**一批点，JSON**

```json
{"格式": "一批点 v0",
 "点": [
  {"名字": "p001", "骨": "sawbone3406",
   "设计": {"L": 30.0, "alpha": 25.0, "h_cut": 24.0, "m": 1.0, "rho_tip": 0.3, "q": 1.5, "lam": 1.6,
            "g_ml": 0.5, "g_ap": 0.5, "n_a": 4.0, "n_p": 4.0, "tau_a": 0.0, "tau_p": 0.0},
   "条件": {"delta_mm": 0.1},
   "理由": "可以没有"}
 ]}
```

`设计` 和 `条件` 里的名字用标签表的列名，数值是物理值。别的键原样带进预测结果。

**一批点，CSV**

一行一个点，列名和标签表一样（`femur_id`、`L`、…、`delta_mm`）。名字取 `name` 列，没有就取 `名字`，再没有就取标签表里行的名字那一列（比如 `row_id`），都没有就用行号。理由取 `reason` 或 `理由` 列。标签表本身就可以当一批点。

## 哪些情况不出数

| 情况 | 怎么办 |
|---|---|
| 预测器文件被改过或坏了（哈希对不上、读不出来） | 整个实验不出数。任务记失败，实验记一条问题 |
| 一批点是空的、有重名、读不出来 | 同上 |
| 一个点没写骨，或骨是预测器没见过的 | 这个点不出数，记进问题。别的点照常 |
| 一个点缺预测器要的输入，或那一格不是数 | 同上 |
| 一个点的某个输入，预测器训练时一直是同一个值，这个点给了别的值 | 同上。预测器没学过这个输入的变化 |

两种情况照常出数，但写明：

- 输入超出训练时的范围：写在"超出训练范围的输入"里。
- 训练时一直不变的输入，这个点没写：按训练时的值算，写在"没写、按训练时的值算的输入"里。

同一种原因的点合成一条问题，里面列出点的名字。

预测器文件有两道核对：文件自带的哈希（`hashes.json`）；启动那一刻算下的整个文件的哈希，后台进程读文件时再对一次。
用训练实验的产出当设置时还有第三道，在地基里：启动时文件的哈希和训练实验记下的对不上，地基不让启动。

## 任务

一个任务，叫"预测"。启动后在后台进程里算。阶段：核对预测器、读一批点、出预测、写产出。停止、重试、暂停和训练插件一样。

## 产出

| 产出 | 文件 | 内容 |
|---|---|---|
| 预测 | `outputs/<第几次>/预测.json` | 用的是哪个预测器（位置、哈希、它的训练数据哈希、它的误差叫什么）；每个点每个目标的预测值、标准差、90% 区间；没出数的点写着原因 |
| 预测表 | `outputs/<第几次>/预测表.csv` | 同一份内容的平表，一行一个点 |

数怎么读：预测值和 90% 区间在原始尺度上。标准差在模型尺度上（目标的变换是 log10 时，是 log10 之后的标准差）。区间 = 模型尺度上的 预测 ± 1.645 × 标准差，再变回原始尺度。
不确定度是什么取决于预测器：高斯过程是模型自带的方差，随机森林是各棵树之间的离散。

## 要知道的

- `model.joblib` 是 pickle。读它等于运行里面的代码。外来的预测器文件只用你信得过的。
- 预测器是用别的版本的 scikit-learn 训练的时候，数照出，同时记一条问题提醒。
- 这个插件不调用训练插件。它只认预测器文件的格式，格式写在 `scalar_train/README.md` 的"产出"里。
