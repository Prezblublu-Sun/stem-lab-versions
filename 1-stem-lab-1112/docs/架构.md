# 架构（八块的划分你 2026-11-13 定了；代码结构是草稿，等你定）

> **这份草稿落后于网页，以网页为准：https://claude.ai/artifact/XmtFbN3JmQH1A4fVa2LhqM 。** 2026-11-13 用户定：case 只指骨这一层（CT、CAD、骨模型）；一批点、策略、设定这些各叫各的，不起总称；块 1 改叫「登记」，代码在 `stemlab/registry/`；实验和登记的东西按使用关系出现在 case 下面，也可以手动挂。这份文件里把所有登记的东西都叫 case 的写法已经不对，等网页上的 12 处定了再重写。

这份文件只写三样：块怎么划分，代码怎么放，每部分做什么。每一块内部的细节另写在 `docs/块/` 下，一块一份。

做法：

- 这份设计只从架构图、你的话和已定的决定出发，不从旧代码出发。设计期间不读旧代码。
- 全部定完之后才有"重组"这一步：把旧代码一段一段对到新结构的位置上，该搬的搬，该改的改，该重写的重写。以新结构为准。

架构图：https://claude.ai/artifact/GHk2bNkDX5Rn1Ndd9fJUm4

## 1. 八块和一样连接件

| # | 块 | 管什么 | 不管什么 |
|---|---|---|---|
| 1 | case | 实验要的每样东西的登记：编号、内容、哈希、来路 | 不管谁用了它，不管内容好不好 |
| 2 | 实验记录 | 一个实验从新建到结束的全部记录：类型、输入、操作、任务、产物、问题；实验的状态怎么变 | 不管任务怎么跑 |
| 3 | 操作台 | 所有改动。你的每个动作在这里变成记录。单个实验的实时进展和这一类的图表也在这里看 | 不管某一类实验具体怎么做 |
| 4 | 仪表盘 | 只读的现状：全部实验里在跑和在排队的、刚结束的、机器、告警 | 不改任何东西，不让任务往前走，不叫插件 |
| 5 | 重建 | 重建这一类实验怎么做 | 另外三类 |
| 6 | FEA | FEA 这一类实验怎么做 | 另外三类 |
| 7 | 代理 | 代理这一类实验怎么做 | 另外三类 |
| 8 | 优化 | 优化这一类实验怎么做 | 另外三类 |
| | 挂点（连接件） | 一类实验怎么接到操作台上；一批点的格式 | |

## 2. 谁可以用到谁

| 块 | 可以用到 |
|---|---|
| case | 无 |
| 实验记录 | 无。它只记 case 的编号 |
| 挂点 | case、实验记录 |
| 操作台 | case、实验记录、挂点 |
| 仪表盘 | case、实验记录，都只读 |
| 重建、FEA、代理、优化 | 只有挂点。四类之间互不相用 |

一类实验的产物给另一类当输入，只经过 case。

## 3. 代码怎么放，每部分做什么

```
stem-lab/
  一页纸.md
  docs/
    架构.md                本文件
    块/                    一块一份：case、实验记录、操作台、仪表盘、重建、FEA、代理、优化、挂点
  stemlab/
    cases/                 块 1 case
    experiments/           块 2 实验记录
    hooks/                 挂点
    desk/                  块 3 操作台
    board/                 块 4 仪表盘
  plugins/
    recon/                 块 5 重建
    fea/                   块 6 FEA
    surrogate/             块 7 代理
    opt/                   块 8 优化
  tests/                   和上面一一对应；测试用的示范插件也放这里
  data/                    case 和实验的数据。不进 git
```

### 块 1 case `stemlab/cases/`

细节见 `docs/块/case.md`。

| 文件 | 做什么 |
|---|---|
| `kinds.py` | case 有哪几种 |
| `register.py` | 登记一个 case：种类、名字、内容、来路。给出编号；同名再登记版本加一。登记只追加 |
| `store.py` | 存内容的三种办法：一个值；原文复制一份；大文件只记位置。算哈希 |
| `lookup.py` | 按编号取；按种类、名字查；把内容交给要用的人（值，或文件的位置） |
| `formats.py` | 有固定格式的种类在登记时核对。现在只有一批点 |
| `verify.py` | 核对：登记有没有被改过；内容和登记时的哈希还一不一致 |

### 块 2 实验记录 `stemlab/experiments/`

| 文件 | 做什么 |
|---|---|
| `log.py` | 一个实验一份只追加的记录：追加一条，读全部，核对有没有被改过 |
| `entries.py` | 记录里有哪几种条目，各记什么：新建、填输入、存定、操作、任务、产物、问题、来历、备注、标签、结束 |
| `rules.py` | 实验的状态，和每种操作在什么状态下能做 |
| `view.py` | 由记录算出现状：状态、每样输入、每个任务走到哪、产物、问题 |

### 挂点 `stemlab/hooks/`

| 文件 | 做什么 |
|---|---|
| `kind.py` | 一类实验要报的五样：类型和版本；输入表；动作；产物表；图表 |
| `handle.py` | 一类的代码能做的事：读一样输入、看任务、报任务状态、登记产物、记问题、加来历、说做完。检查和图表拿到的是只读的 |
| `load.py` | 找到四类的插件。装不上的报出来，别的照常 |
| `call.py` | 叫一类的某个动作。出错不往外抛，记成那个实验的问题；同一个报错连着出现只记第一次。取图表的数据出错不写进记录 |
| `points.py` | 读和写一批点 |
| `entry.py` | 带代码的 case 怎么调用：策略、预测器、推导量定义各一个固定的入口 |
| `tools.py` | 两个小函数：看一个进程还在不在；算文件的哈希 |

### 块 3 操作台 `stemlab/desk/`

| 文件 | 做什么 |
|---|---|
| `actions.py` | 你的每个动作一个函数：登记、新建、填、启动、暂停、继续、停止、重试、刷新、备注、标签。每个都是：查规则，记一条，需要时叫插件 |
| `views.py` | 看的东西：一个实验的全部记录；所有实验的列表；case 清单；四类各要什么；并排比两个实验的输入 |
| `progress.py` | 一个实验的实时进展：每个任务的阶段、各阶段用了多久、问题、已经出来的产物；这一类提供的图表。比仪表盘细 |
| `watch.py` | 定时叫所有运行中实验的插件报任务状态 |
| `locks.py` | 同一个实验一次只让一处动；值守同一时刻只有一处 |
| `cli.py` | 命令行用法 |
| `web.py`、`page.html` | 网页用法。只绑本机 |

### 块 4 仪表盘 `stemlab/board/`

| 文件 | 做什么 |
|---|---|
| `experiments.py` | 在跑和在排队的实验及其任务；刚结束的。只读实验的记录 |
| `machines.py` | 机器：Linux 队列、Windows 求解槽、训练进程、磁盘。只读 |
| `alerts.py` | 告警的线和判断。只显示，不动作 |
| `web.py`、`page.html` | 只读的网页，自己定时更新 |

### 块 5 到 8 四类 `plugins/`

每一类都有一个 `plugin.py`，把这一类接到操作台上：报输入表、产物表，写七个动作。每一类还有一个 `charts.py`，提供这一类的图表：插件只给数据和图的种类，操作台统一画。其余文件是这一类自己的做法。下面是初稿，定每一类时和你一起细化。

| 类 | 文件 | 做什么 |
|---|---|---|
| 重建 `recon/` | `chain.py` | 按登记的方法和参数，从骨源重建 |
| | `review.py` | 人工检查和人工修改怎么记、怎么等 |
| | `model.py` | 写出骨模型 |
| FEA `fea/` | `jobs.py` | 一批点变成作业清单；作业号 |
| | `submit.py` | 把作业排到机器上；停、重排 |
| | `stages.py` | 每个作业走到哪：排队、建模、求解、后处理、完成或失败 |
| | `export.py` | 导出每行的标签、界面场、整体场 |
| | `derived.py` | 推导量，定义带版本 |
| | `judge.py` | 按判据判定 |
| 代理 `surrogate/` | `data.py` | 读训练数据，按划分切成训练和留出 |
| | `targets.py` | 目标：标量，或整体应变场 |
| | `train.py` | 一次训练，产出预测器 |
| | `predict.py` | 用一个预测器对一批点出预测 |
| | `report.py` | 误差报告 |
| 优化 `opt/` | `inputs.py` | 读目标和约束、候选池、预测器、已有数据 |
| | `run.py` | 照着跑一份登记的策略或算法 |
| | `points.py` | 写出一批点，每个点带理由 |

FEA 的"模型版本"是一个登记过的 case（冻结内核），不是插件里的代码。

## 4. 数据怎么放

```
data/
  cases/
    register.jsonl         case 的登记，只追加
    C0001/                 这个 case 存下来的内容
  experiments/
    E0001/
      record.jsonl         这个实验的记录，只追加
      outputs/             产物（同时登记成 case）
      work/                这一类的代码自己用的地方
```

## 5. 接下来

| 步 | 做什么 |

| 1 | 你定这份总图 |
