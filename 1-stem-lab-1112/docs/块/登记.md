# 块 1 case（草稿，等你定）

> **这份草稿落后于网页，以网页为准：https://claude.ai/artifact/XmtFbN3JmQH1A4fVa2LhqM 。** 2026-11-13 用户定：case 只指骨这一层（CT、CAD、骨模型）；一批点、策略、设定这些各叫各的，不起总称；块 1 改叫「登记」，代码在 `stemlab/registry/`；实验和登记的东西按使用关系出现在 case 下面，也可以手动挂。这份文件里把所有登记的东西都叫 case 的写法已经不对，等网页上的 12 处定了再重写。

代码在 `stemlab/cases/`，数据在 `data/cases/`。总图见 `docs/架构.md`。

## 1. 管什么，不管什么

管：

- 登记。外面拿来的东西和实验的产物，都登记成 case。
- 给编号，定名字和版本，存内容，算哈希，记来路。
- 按编号取，按种类和名字查。
- 核对：登记有没有被改过；内容和登记时还一不一致。

不管：

- 一个 case 被哪些实验用过。那由实验记录算出来。
- 内容好不好、对不对。只有一批点在登记时核对格式。
- 改和删。登记后不改，不删。

## 2. 一个 case 记什么

| 项 | 内容 |
|---|---|
| 编号 | `C0001` 起，系统给，不重复，不复用 |
| 种类 | 第 3 节清单里的一个 |
| 名字 | 你起的。同一样东西的不同版本用同一个名字 |
| 版本 | 这个名字第几次登记，从 1 起 |
| 存法 | 一个值；原文复制一份；只记位置 |
| 内容 | 值本身，或存下来的那一份在哪，或原文件在哪 |
| 哈希 | 登记时算。文件夹的哈希是里面每个文件的相对位置和内容合起来算 |
| 来路 | 外面拿来的：从哪拿的、什么时候拿的、你写的一句说明。实验的产物：哪个实验的哪一样产物 |
| 登记时间 | 系统记 |

## 3. 种类

架构图上写了八种：骨模型、一批点、数据、预测器、策略、目标、定义、设定。四类的输入表里另有三样对不上这八种：骨源、候选池、冻结内核。这里要你定，见第 9 节。

规则：

- 种类是一张固定的清单，放在 `kinds.py`。登记时种类不在清单里就拒绝。
- 四类的输入表里，每样输入写明收哪种或哪几种。种类不对的 case 填不进去。
- 加一个种类，先改这份文档。

## 4. 每个文件里有什么

### `kinds.py`

| 函数 | 做什么 |
|---|---|
| `KINDS` | 种类的清单 |
| `is_kind(种类)` | 这个词在不在清单里 |

### `store.py`

| 函数 | 做什么 | 读 | 写 |
|---|---|---|---|
| `hash_value(值)` | 算一个值的哈希 | | |
| `hash_path(位置)` | 算一个文件或文件夹的哈希 | 那个文件 | |
| `keep_copy(编号, 原文件)` | 把原文复制一份存下来，返回存在哪 | 原文件 | `data/cases/<编号>/` |

### `register.py`

| 函数 | 做什么 | 读 | 写 |
|---|---|---|---|
| `register_external(种类, 名字, 内容, 存法, 从哪拿的, 什么时候, 说明)` | 登记一个外面拿来的东西，返回 case | 登记、原文件 | 登记；复制时写内容 |
| `register_output(种类, 名字, 位置, 实验编号, 产物名)` | 登记一个实验的产物，返回 case。存法是只记位置，位置在那个实验的产物文件夹里 | 登记、产物文件 | 登记 |

两个函数做的步骤相同：

1. 种类在不在清单里。
2. 同名的 case 已有的话，种类要相同；版本取已有的最大版本加一。
3. 有固定格式的种类先核对格式，不符合就拒绝并说出是哪一条。
4. 给编号，存内容，算哈希。
5. 往登记里追加一条。

两处同时登记，不会拿到同一个编号。

### `lookup.py`

| 函数 | 做什么 | 读 |
|---|---|---|
| `get(编号)` | 一个 case 登记的全部内容 | 登记 |
| `find(种类, 名字)` | 查 case。两个条件都可以不给 | 登记 |
| `latest(名字)` | 这个名字最新的版本 | 登记 |
| `content(编号)` | 把内容交给要用的人：值，或文件的位置 | 登记 |

### `formats.py`

| 函数 | 做什么 |
|---|---|
| `check(种类, 内容)` | 这个种类有固定格式就核对，返回不符合的地方；没有固定格式的直接过 |
| `check_points(内容)` | 一批点的核对：没有"格式"；点是空的；名字重复；缺"骨"；缺"设计"；缺"条件"。JSON 和平的 CSV 两种都收 |

一批点的格式写在 `docs/块/挂点.md`。

### `verify.py`

| 函数 | 做什么 | 读 |
|---|---|---|
| `verify_register()` | 登记有没有被改过或删过。返回哪一条有问题 | 登记 |
| `verify_case(编号)` | 这个 case 现在的内容，哈希和登记时还一不一致 | 登记、内容 |

## 5. 数据

```
data/cases/
  register.jsonl      一行一条登记，只追加。每条带序号和上一条的哈希
  C0001/              存法是"复制"的 case，存下来的那一份
```

- 存法是"一个值"的，值就写在登记那一条里。
- 存法是"只记位置"的，这里不存内容。

## 6. 和别的块怎么连

| 谁 | 用 case 的什么 | 什么时候 |
|---|---|---|
| 操作台 | `register_external` | 你登记外来的东西 |
| 操作台 | `get` | 你给一样输入填 case 编号时，查种类对不对 |
| 操作台 | `verify_case` | 启动时，每样输入核一遍 |
| 操作台 | `find`、`verify_register` | 看 case 清单；核对 |
| 挂点 | `register_output` | 一类的代码登记产物时 |
| 挂点 | `get`、`content` | 一类的代码读一样输入时 |
| 仪表盘 | `get` | 显示刚结束的实验产出了什么。只读 |

case 这一块不用别的任何一块。实验记录里只记 case 的编号；启动时由操作台把版本、哈希、来路抄进实验的记录。

## 7. 规则

- 登记后不改，不删。要改就再登记一次，是新的版本。
- 同一个名字只能是同一个种类。
- 只记位置的 case，原文件后来被改了：`verify_case` 不过，用它的实验不让启动。
- 实验的产物也一样：产物文件被改过，拿它当输入的实验不让启动。

## 8. 验收

每条一个测试，先证明它能不过。

| # | 做什么 | 通过标准 |
|---|---|---|
| O1 | 登记一个外来的文件，存法是复制 | 得到编号；种类、名字、版本 1、哈希、来路都记下；原文件之后改了，存下来的那一份不变，`verify_case` 过 |
| O2 | 登记一个外来的文件，存法是只记位置，之后改原文件 | `verify_case` 不过，并说出是哪个 case |
| O3 | 登记一个值 | 取回来的值和登记的相同 |
| O4 | 同一个名字再登记一次 | 版本是 2，编号是新的，版本 1 还在；同名换一个种类被拒 |
| O5 | 用清单里没有的种类登记 | 被拒 |
| O6 | 登记一批点 | 符合的登记得上；六种坏法每一种都被拒并说出是哪一条 |
| O7 | 手改登记里的一条，再手删一条 | `verify_register` 指出是哪一条 |
| O8 | 四处同时各登记 100 次 | 400 个编号不重复；登记完好 |
| O9 | 登记一个实验的产物 | 来路是实验编号和产物名 |
| O10 | 检查 `stemlab/cases/` 的 import | 不 import 别的块 |
