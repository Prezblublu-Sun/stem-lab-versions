## 1. 架构

架构图：https://claude.ai/artifact/GHk2bNkDX5Rn1Ndd9fJUm4

### 1.1 系统只有两样东西

| | 操作台 | 仪表盘 |
|---|---|---|
| 给你什么 | 帮你操作实验，并把每次操作记下来 | 实时的任务现状 |
| 会不会改东西 | 会。所有改动都从这里走 | 不会，只读 |
| 怎么运行 | 你要操作的时候用 | 一直开着，消耗低，不需要 agent 在场 |

### 1.2 单位是实验

一个实验 = 一次独立的启动。它有四样：

| | 内容 |
|---|---|
| 类型 | 重建、FEA、代理、优化，四选一 |
| 输入 | 这类实验要的几样东西。每样都是一个登记过的物件 |
| 任务 | 启动后实际在跑的东西。仪表盘看的就是它 |
| 产物和记录 | 跑出来的物件；从新建到结束的全部记录 |

四类互不绑定，没有固定的先后。任何一个填齐输入就能单独启动。

### 1.3 输入是物件，来路两种

物件的种类：骨模型、一批点、数据、预测器、策略、目标、定义、设定。

| 来路 | 例子 | 记什么 |
|---|---|---|
| 系统里某个实验的产物 | FEA 实验产出的数据；代理实验产出的预测器 | 哪个实验产的 |
| 从外面登记进来的 | 你在别处训练好的模型；手写的一份点；别人给的策略脚本；一份 CAD | 从哪拿的，什么时候，文件的哈希 |

对实验来说两种来路没有区别。所以一类实验可能是另一类的前置，但从不是必须的。

### 1.4 四类实验各要什么、产出什么

| 类型 | 输入 | 可以用系统里的 | 也可以用外面拿来的 |
|---|---|---|---|
| 重建 | 骨源：CT 或 CAD | | 外面拿来的文件 |
| | 重建方法和参数 | 登记过的设定 | 别处的一套流程 |
| | 人工修改 | | 你在操作台里记 |
| FEA | 骨模型 | 重建实验的产物 | 一份 CAD，或别处重建好的模型 |
| | 一批点：设计和条件 | 优化实验的产物 | 手写的点，或别处选好的点 |
| | 模型版本 | 登记过的冻结内核 | |
| | 导出清单和推导量定义 | 登记过的设定 | |
| | 判据（可选） | 登记过的设定 | |
| 代理 | 训练数据 | FEA 实验的产物 | 别处来的数据 |
| | 模型和训练配置 | 登记过的设定 | 直接登记一个外面训练好的模型，跳过训练 |
| | 目标：标量，或整体应变场 | 登记过的设定 | |
| | 训练和留出的划分 | 登记过的设定 | |
| | 一批点（只出预测时） | 优化实验的产物 | 手写的点 |
| 优化 | 目标和约束 | 登记过的设定 | |
| | 策略或算法 | 登记过的策略 | 你在别处调好的脚本或配置 |
| | 候选池 | 登记过的候选池 | 别处生成的一批候选 |
| | 预测器（可选） | 代理实验的产物 | 外面训练好的模型 |
| | 已有数据（可选） | FEA 实验的产物 | 别处来的数据 |

| 类型 | 启动后的任务 | 产物 |
|---|---|---|
| 重建 | 一次重建，加一次人工检查 | 一个骨模型 |
| FEA | 每个点一个作业：排队、建模、求解、后处理、完成或失败 | 数据：每行的标签、界面场、整体场 |
| 代理 | 一次训练；或者用一个预测器对一批点出预测 | 预测器和误差报告；或一份预测 |
| 优化 | 一次选点 | 一批点，每个点带理由 |

### 1.5 系统外的

| 不在系统里 | 说明 |
|---|---|
| 轮次 | 哪几个实验算一轮、怎么接，是你的安排。可以用标签自己标，系统不解释标签 |
| 怎么比较策略、怎么调优化 | 在外面做。调好了登记成新的物件，再启动实验 |
| 下一步做什么 | 系统不替你定 |

## 2. 程序怎么分

| 部分 | 文件 | 放什么 | 可以用到 |
|---|---|---|---|
| 公共 | `stemlab/record.py` | 实验记录。只追加 | 无 |
| 公共 | `stemlab/objects.py` | 物件登记。只追加 | `record` |
| 公共 | `stemlab/plugins.py` | 挂点：插件报什么、怎么找它、怎么叫它 | `record`、`objects` |
| 操作台 | `stemlab/console.py` | 命令行用法。所有改动都从这里走 | 上面三个、`watch` |
| 操作台 | `stemlab/watch.py` | 定时值守 | `record` |
| 操作台 | `stemlab/console_web.py` | 网页用法。每件事都经过 `console` | `console`、`watch` |
| 仪表盘 | `stemlab/machines.py` | 机器信息的采集。只读 | 无 |
| 仪表盘 | `stemlab/dashboard.py` | 只读的网页 | `record`、`objects`、`machines` |
| 四类 | `plugins/recon/`、`fea/`、`surrogate/`、`opt/` | 重建、FEA、代理、优化各一个插件 | 只有 `stemlab.plugins` |

四条规矩，每条一个测试：

- 一类的代码只在自己的插件里。公共部分、操作台、仪表盘的文件里不出现四类的名字。
- 插件只 import `stemlab.plugins`，不 import 别的公共文件，不 import 别的插件。
- 仪表盘不碰插件，不碰操作台，不往盘上写。
- 网页操作台自己不碰记录和物件登记。

测试要用的示范插件放在 `tests/` 里，不算第五类，操作台上看不到它。

## 3. 接口

块和块之间只靠这四样相连。要改其中任何一样，先回来改本文件。

### 3.1 实验记录、3.2 物件

内容见 `docs/实验记录格式.md`。

### 3.3 挂点

一个插件报四样：

| # | 报什么 | 内容 |
|---|---|---|
| 1 | 类型和版本 | 类型是四类之一 |
| 2 | 输入表 | 每样：名字、是不是必须、收哪种物件、说明、标准选项（可以没有） |
| 3 | 动作 | 检查、启动、报任务状态、暂停、继续、停止、重试 |
| 4 | 产物表 | 每样：名字、是哪种物件、说明 |

第 2、4 两样就是第 1.4 节的表。"检查"可以不写：启动前叫一次，它说不过，就不存定、不启动，把原因告诉你。

插件只能经挂点做这些事：

| 插件能做的 | 说明 |
|---|---|
| 读一样输入 | 内容（一个值，或文件的位置）和它的物件信息（编号、种类、版本、来路、哈希）。只读 |
| 看现在各任务的状态 | |
| 报一个任务的状态 | 五种状态之一，加自己的阶段名和机器 |
| 登记一样产物 | 系统算哈希，登记成物件 |
| 记一条问题 | |
| 加来历 | 比如 FEA 的内核哈希 |
| 说全部做完了 | |
| 用两个文件夹 | 放产物的；自己的 |
| 用两个小函数 | 看一个进程还在不在；算文件的哈希 |

公共部分怎么对待插件：

- 插件的任何动作出错，不往外抛，记成这个实验的一条问题。
- 报任务状态时同一个报错连着出现，只记第一次。报错变了或恢复正常时追加一条，写明连着出现了几次。
- 一个插件装不上，报出来，别的照常。拔掉一个插件，它的旧实验照样能看、能写备注。

### 3.4 一批点

"一批点"是一种物件。优化实验产出它，FEA 实验和代理实验的出预测吃它。

写出来的一律是一个 UTF-8 的 JSON 文件：

```json
{"格式": "一批点 v0",
 "点": [
  {"名字": "p001",
   "骨": "sawbone3406",
   "设计": {"L": 30.0, "alpha": 25.0, "h_cut": 24.0},
   "条件": {"delta_mm": 0.1, "mu": 0.3},
   "理由": "可以没有"}
 ]}
```

| 键 | 内容 | 必须 |
|---|---|---|
| `格式` | 固定写 `一批点 v0` | 是 |
| `点` | 列表，一个点一项，不能是空的 | 是 |
| `名字` | 这一批里不重复。同一个点在优化、FEA、代理三处用同一个名字 | 是 |
| `骨` | 骨的名字 | 是 |
| `设计` | 设计变量名到数值，物理值。名字用标签表的列名 | 是 |
| `条件` | 条件名到数值。名字用标签表的列名 | 是，可以是空的 |
| `理由` | 选它的理由 | 否 |
| 别的键 | 谁加的谁用。别的插件不读，也不丢，原样带着 | 否 |

- 读的时候也收一张平的 CSV 表：一行一个点，列名和标签表一样，名字列叫 `name`，理由列叫 `reason`。
- 没写的条件：每个插件用自己的默认，并在自己的产物里写明实际用的值。
- 不符合的在登记时就被拒绝，并说出是哪一条。所以插件拿到的一批点都是符合的。

## 4. 操作台

两种用法，是同一个操作台：命令行 `python -m stemlab`；网页，只绑本机，端口 8792。命令有英文和中文两种写法。

| 命令 | 做什么 |
|---|---|
| 登记 | 登记一个外来的东西：种类、名字、内容、从哪拿的。给出物件编号 |
| 物件 | 看登记过的物件；看一个物件被哪些实验用过 |
| 类型 | 四类各要什么输入、产出什么 |
| 新建 | 选一类，新建一个实验，给出实验编号 |
| 填 | 启动前给一样输入填一个物件编号。也可以一步做完：登记并填上 |
| 启动、暂停、继续、停止、重试 | 操作，每次记一条 |
| 刷新 | 叫插件看一眼任务走到哪了 |
| 看、列表 | 一个实验的全部记录；所有实验一行一个 |
| 备注、标签 | 随时可以加 |
| 并排比 | 挑两个实验，输入逐样并排 |
| 核对 | 核对记录和物件有没有被改过 |
| 值守 | 定时叫所有运行中实验的插件报任务状态 |

| 操作 | 实验是什么状态时能做 | 做完变成 | 叫插件的哪个动作 |
|---|---|---|---|
| 新建 | 随时 | 未启动 | 不叫 |
| 启动 | 未启动，必须的输入都填了，检查过了 | 运行中 | 检查，启动 |
| 暂停 | 运行中 | 已暂停 | 暂停 |
| 继续 | 已暂停 | 运行中 | 继续 |
| 停止 | 运行中、已暂停 | 已停止 | 停止 |
| 重试 | 已停止、已结束 | 运行中 | 重试 |
| 刷新、值守 | 运行中 | 不变 | 报任务状态 |
| 插件说做完 | 运行中 | 已结束 | |

- 任务状态要有人叫插件去看才会更新。网页操作台开着时值守跟着开着；不开网页时用"值守"命令。
- 同一个实验一次只让一处动。一个存放处同一时刻只有一处在值守。
- 网页操作台能改东西，所以没有换地址的开关；改东西的请求要带一个专门的请求头。

## 5. 仪表盘

一个本机网页，端口 8791，自己定时更新。

| 显示 | 内容 | 从哪读 |
|---|---|---|
| 在跑和在排队的实验 | 类型、说明、每个任务的状态和阶段 | 实验记录 |
| 刚结束的 | 成功还是失败，产出了什么 | 实验记录 |
| 机器 | Linux 队列；Windows 求解槽；训练进程；磁盘 | 本机直接读；Linux 开一条只读的长连接，循环跑在那一头 |
| 告警 | 比如磁盘低于一条线。只显示，不动作 | 线写在一份配置里 |

- 只收读的请求。不叫任何插件，不碰操作台，不往盘上写。
- 它不会让任务往前走。
- 送到远端跑的命令只有读，清单要你先同意。仪表盘关掉，那一头的循环跟着退出。

## 6. 骨架怎样算搭好

每条是一个或几个自动测试，都先证明它能不过。全部通过才给四类接上执行。

| # | 验什么 | 通过标准 | 目标 |
|---|---|---|---|
| S1 | 记录只追加 | 编号不重复不复用；手改一条，核对能指出是哪一行 | G3 |
| S2 | 物件登记 | 登记一个外来的文件，得到编号，记下种类、来路、哈希；之后原文件改了，登记的那一份不变；登记不能改、不能删 | G2 |
| S3 | 输入填物件 | 同一个物件填进两个实验，两处记的是同一个编号；种类不对的物件填不进去 | G2 |
| S4 | 启动时存定 | 存下每样输入的物件编号、版本、哈希、来路；启动后改输入被拒；缺必须的输入被拒；物件的文件被改过，不让启动 | G3 |
| S5 | 产物是物件 | 实验的产物自动登记成物件，来路是这个实验；能填进另一个实验 | G1、G2 |
| S6 | 四类 | 操作台上正好四类；每类报的输入和产物和第 1.4 节的表一致；每类都能新建、填输入、看 | G1 |
| S7 | 走通一遍 | 用示范插件：新建、填、启动、任务状态变化、产物、结束。记录的各项都在 | G3 |
| S8 | 出问题不拦别的 | 任务失败、插件出错、插件装不上，都记成问题；别的任务、实验、插件照常；同一个报错连着出现只记第一次 | G7 |
| S9 | 四类隔开 | 第 2 节的前两条规矩各有测试；拔掉一类的插件，它的旧实验照样能看，另外三类照常 | G6 |
| S10 | 改动只从操作台走 | 网页操作台每件事都经过命令行那一层；只绑本机；没带专门请求头的写请求被拒；两处同时动同一个实验，插件只被叫一次；值守只有一处 | G4 |
| S11 | 仪表盘只读 | 开着仪表盘前后盘上的文件不变；不碰插件和操作台；送到远端的命令只有读 | G5 |
| S12 | 仪表盘显示四样 | 在跑和在排队的、刚结束的、机器、告警都有；告警没有任何动作 | G5 |
| S13 | 整体 | 在网页上新建并启动，之后不再点任何东西。值守让任务自己走完；仪表盘跟着变；命令行和网页共用一份记录 | G4、G5 |
| S14 | 一批点 | 登记一批点时核对：符合第 3.4 节的登记得上；不符合的被拒绝，并说出是哪一条 | G9 |
| S15 | 一条命令跑全部测试 | 公共部分、操作台、仪表盘和四个插件的测试都跑到 | G10 |
| S16 | 仪表盘读远端 | 实际连一次 Linux，只读；关掉后那一头的循环退出；开几小时，进程和连接都干净 | G5 |

## 7. 搭的顺序

每块一个独立的对话，开工前读一页纸和本文件，不读旧对话的历史。

| # | 块 | 建什么 | 验收 | 前提 |
|---|---|---|---|---|
| 1 | 记录和物件 | 实验记录；物件登记；`docs/实验记录格式.md` 里的全部内容 | S1、S2 | 无 |
| 2 | 操作台不执行的部分 | 登记、物件、类型、新建、填、看、列表、备注、标签、核对。命令行和网页。四个插件先只报输入表和产物表 | S3、S6、S14 | 第 1 块 |
| 3 | 启动和值守 | 挂点的动作；启动时存定；任务状态；产物登记成物件；问题；值守；一个实验一次只让一处动。用示范插件走通 | S4、S5、S7、S8、S9、S10、S15 | 第 2 块 |
| 4 | 仪表盘 | 第 5 节的四样 | S11、S12、S16 | 第 1 块；读远端要你同意一份只读命令清单 |
| 5 | 四类逐类接上执行 | 见下表。一类一个对话，只写自己那一类的插件 | 见下表 | 第 3 块；每一类要你明说 |
| 6 | 并排比；把旧系统的实验导进来 | 并排比两个实验的输入；旧系统的实验只读导入成记录和物件 | 页面检查；行数、作业号和旧清单相同 | 第 3 块 |

第 4 块可以和第 2、3 块同时做。S13 要第 3、4 块都做完才能验。

| 类 | 接上什么 | 验收 |
|---|---|---|
| 优化 | 照着跑一份登记过的策略，产出一批点 | 只用外面登记的物件就能启动并走完；产物是第 3.4 节的一批点；用一份真实的策略试一次 |
| 代理 | 训练标量预测器；对一批点出预测；整体应变场的预测器 | 只用外面登记的物件就能启动并走完；读得进第 3.4 节的一批点；由预测的场重算的指标和真值比 |
| FEA | 冻结内核 8 个文件原字节搬，作业号照抄；一个点一个作业；导出标签、界面场、整体场；推导量；判定 | 代码哈希是 `6d7af243d0`；旧的 84 行作业号逐个相同；读得进第 3.4 节的一批点；导出对 `db3406` 的 `v0.14` 逐格核；旧数据的文件前后不变。往 Linux 写要你明说 |
| 重建 | 开源重建链 | 只用外面登记的物件就能启动并走完；取几根已重建过的骨，结果相同 |

规矩：

- 第 6 节没全过之前，不给四类接执行。
- 一个对话只做一块。第 5 块里一个对话只做一类。
- 做一类的对话只写自己那一类的插件。看到别处的问题，记进 `docs/做的时候看到的问题.md`，不顺手改。
- 每块做完向你交代：做了什么、用什么验证的、哪些没验证。写进第 10 节。
